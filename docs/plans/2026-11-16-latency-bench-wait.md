## 1. Ожидание приветствия

Окно считает строки транскрипта, дописанные до его приветствия, прошлыми и не разбирает. Стенд ждёт, пока в разметке
вывода окна появится конец первой строки; окно вышло раньше или не дождался за 30 с — отказ с текстом ошибок окна.

**Готово, когда:** с двойником `claude` стенд проходит; при старте окна, задержанном на 3 с, прежний стенд отказывает
(«ответа нет за 120 с»), новый проходит.

*Подтверждено:* оба прогона с двойником `claude` и обёрткой `bash`, задерживающей запуск `meeting-candidate` на 3 с:
прежний — отказ на первой реплике, новый — обе реплики с ответом. Числа задержки в `docs/measurements.md` не меняются:
прежний стенд при гонке отказывал, а не искажал замер.

## 2. Закрытие

*Подтверждено:* саморевью (Opus): блокирующего нет. По находкам: окно, упавшее до приветствия, ждало все 30 с, а
отказ называл файл ошибок, уже удалённый ловушкой выхода, — теперь отказ сразу (`kill -0` окна) с текстом ошибок, так
же по сроку ответа 120 с; выход стенда оставлял окно живым (`$!` конвейера — PID разметки, а не окна) — окно теперь
запускается с подстановкой процесса, ловушка гасит его самого. Проверено с двойником `claude`: обычный прогон,
старт окна на 3 с позже, падение окна до приветствия (отказ за 0 с с текстом ошибки), `TERM` посреди ответа — окон
после выхода не остаётся. Ретро — грабля bash про `$!` конвейера в глобальные правила.
