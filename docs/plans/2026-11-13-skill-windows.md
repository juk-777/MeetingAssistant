## 1. Тесты скилла под Git Bash

`tests/meeting-skill/run.sh`: заглушка `jq` на весь прогон роняет любой вызов. `current.json` в тестах
пишется так, как его пишет приложение, — без `jq`. Под Git Bash тесты `install-skill.sh` и `release-version.sh`
печатаются как «пропущен» с причиной и входят в итог.

**Готово, когда:** под WSL и Git Bash падают ровно тесты, которые зовут `jq` в скриптах скилла, — это красная
сторона этапа 2; тесты скриптов разработчика под Git Bash пропущены, под WSL идут.

*Подтверждено:* в WSL упало 10 — все на «jq вызван» или ожидании `id` в `meeting-start`.

## 2. `current.json` без `jq`

`meeting-dir` и `meeting-start` читают `id` и `directory` функцией на bash: строка JSON с `\\`, `\"`, `\/`,
`\uXXXX` и суррогатными парами.

**Готово, когда:** весь набор зелёный в WSL и Git Bash; тесты на `current.json` в виде приложения (путь
Windows с `\\`, кириллица, эмодзи `😀`, `\"` в имени). Мутации: снять разбор `\\`, снять разбор
`\uXXXX`, вернуть `jq` — падают свои тесты.

*Подтверждено:* WSL 51/0, Git Bash 51/0 (7 пропущено). Мутанты убиты: `\\` оставлен как есть (3 теста),
`\u` не разбирается, суррогатная пара не собирается, `jq` в `meeting-dir` (10 тестов) и в `meeting-start` (2).
Попутно: два теста сверки моделей под неинтерактивным Git Bash падали на `grep -P` без локали UTF-8 — им задана
`LC_ALL=C.UTF-8`.

## 3. Пути через `cygpath`

Путь для окна Windows — `cygpath -w` или `wslpath -w` (скрипт `windows-path`); путь Windows в локальный — в WSL
`wslpath -u`, в Git Bash как есть. Скрипт, вызванный по пути с обратными косыми, находит соседей.

**Готово, когда:** тесты: заглушка `cygpath` получает каталог встречи для уточнения, словарь и корень, окно —
её ответ; скрипт, вызванный по пути с `\`, находит соседей (под Git Bash; в WSL такого пути нет). Мутации: снять
`cygpath -w`, снять нормализацию пути скрипта — падают свои тесты.

*Подтверждено:* `cygpath -u` для пути из `current.json` убран — Git Bash открывает `C:\…` сам. Нормализация пути
скрипта (`\` → `/`) убрана: три мутанта «снять её» под Git Bash выжили, потому что `dirname` Git Bash сам делит
путь по `\`; тест вызова по пути Windows оставлен как защита свойства. Мутации `windows-path` (снят `cygpath`,
`wslpath` раньше `cygpath`), снятый перевод словаря, корня и каталога уточнения — убиты в WSL.

## 6. Живая проверка в Claude Code для Windows

На машине владельца, скилл из рабочей копии (`--plugin-dir`, установленный плагин выключен): `/meeting start`,
события и подсказка (терминал, уведомление, `hints.md`), Ctrl+C и `конец записи`, `/meeting уточни`,
`/meeting протокол`.

**Готово, когда:** каждый шаг пройден, итог записан сюда.

*Подтверждено (13.11.2026, Claude Code для Windows 2.1.319, Git for Windows, bash 5.2):* встреча 2 мин —
окно записи открылось, `Monitor` с `meeting-watch` в Git Bash, 4 пробуждения (2 подсказки, 2 молчания, запись
в `hints.md` через 15–19 с после события), уведомления Windows видны, `конец записи` пришёл, `/meeting уточни` —
`transcript.whisper.md`, `/meeting протокол` — `protocol.md` из двух транскриптов. Все скрипты — инструментом
Bash; `${CLAUDE_SKILL_DIR}` подставился как `D:/…` (прямые косые), «Base directory» — `D:\…`.

Найдено на проверке: Ctrl+C в окне записи не останавливал запись. Claude Code для Windows запускает Git Bash
новой группой процессов — Ctrl+C выключен (`ConsoleFlags` = 1 у `bash.exe`, `cmd.exe` и `meeting.exe`, 0 у
`claude.exe`), флаг наследуется окном. `meeting-start` и `meeting-refine` снимают его (`SetConsoleCtrlHandler`)
перед открытием окна; дочерний процесс без снятия — 1, со снятием — 0. Автотеста нет: `powershell.exe` в тестах —
заглушка. Повторная встреча (35 с) после правки: Ctrl+C остановил запись, окно показало итог и ждёт клавишу,
`конец записи` пришёл в сессию.
