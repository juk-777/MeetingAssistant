## 1. Домен

Domain: value object сетки экрана — яркость ячеек 64×36, строится из пикселей RGB снимка любого размера (среднее по
ячейке); правило `ScreenChangePolicy` с константами (порог яркости 4, устоялась 3 с, доля — 5 ячеек, промежуток
10 с) и состоянием наблюдения: опорная сетка, время последнего изменения каждой ячейки, время прошлой смены.
`Observe(сетка, время)` отвечает, сменился ли экран; при смене опорной становится эта сетка.

**Готово, когда:** тесты — все свойства «Домен» из «Проверяемости» спеки; мутации: каждый порог (4 → 5, 5 ячеек →
4, 3 с → 2.9, 10 с → 9.9), снятие «устоялась», опорная — прошлая сетка вместо записанной, первый снимок не смена —
роняют свои тесты.

*Подтверждено:* тесты `ScreenChangePolicyTests` (правило и сетка); 14 мутаций убиты — порог яркости, «устоялась»
(сравнение и снятие), доля ячеек, промежуток (сравнение и снятие), опорная — прошлая сетка, первый снимок, запись
опорной, обновление прошлой сетки, веса каналов яркости, строка ячейки, округление, проверка размера. Пороги в
тестах — выражения от констант, поэтому мутация значения константы тестом не ловится по замыслу; ловится сравнение.
Шаг снимка (1 с) — константа правила `CaptureInterval`: «устоялась» считается по снимкам.

## 2. Application

Порты: `IScreenSource` (снимок монитора: размер и пиксели RGB), запись смены — файл снимка и строка `screen.log` через
порт хранилища встречи. Цикл `ScreenWatcher`: раз в секунду по `TimeProvider` снимок → сетка → правило → при смене
запись; живёт, пока идёт запись встречи, и останавливается вместе с ней; сбой снимка — лог, цикл продолжается. Без
источника экрана цикл не запускается.

**Готово, когда:** тесты на двойниках и `FakeTimeProvider`: остановка записи останавливает цикл, сбой одного снимка
не останавливает ни цикл, ни запись; мутации снятия остановки и снятия перехвата сбоя роняют свои тесты.

*Подтверждено:* тесты `ScreenWatchTests` через `IMeetingRecorder` (цикл живёт в жизни записи); 4 мутации убиты —
снятие остановки (запись не кончается), без источника не наблюдать, снятие перехвата сбоя, запись без смены. Порядок
«файл раньше строки» — внутри одного порта записи, проверяется в Infrastructure (этап 3).

## 3. Infrastructure

`Screen/`: свой PNG (сигнатура, IHDR, IDAT через `ZLibStream`, IEND, CRC-32) и уменьшение до 1568 по длинной
стороне с сохранением пропорций; захват Windows — GDI `BitBlt` монитора по номеру (`EnumDisplayMonitors`, основной —
первым), процесс DPI-aware по мониторам; Linux X11 — `XGetImage` корневого окна через `libX11`, отказы: Wayland, нет
дисплея, нет библиотеки, номер монитора. Хранилище встречи: `screen/<чч-мм-сс>.png` по времени от начала, строка
`<epoch>\t<файл>` в `screen.log`.

**Готово, когда:** тест PNG разбирает файл сам — сигнатура, CRC кусков, пиксели после распаковки; уменьшение —
пропорции и предел; формат `screen.log` и имя файла; захват Windows и X11 тестами не покрыт — подтверждается живым
прогоном (этап 8, Linux — приёмка #16); мутации CRC, фильтра строк и предела уменьшения роняют свои тесты.

*Подтверждено:* 12 тестов `ScreenFilesTests`, `ScreenCaptureTests` (формат `screen.log` и имени, разбор PNG
независимым CRC и распаковкой, уменьшение, отказ записи снимка без строки, отказы захвата на Linux); 7 мутаций убиты —
строка раньше файла, CRC без финального XOR и с нулевым началом, фильтр строки, округление среднего, усреднение по
одной строке, отбрасывание дроби высоты (две последние выжили в первом прогоне — тест усилен). Мутант «`<` вместо
`<=` у предела» — равносильный: снимок ровно 1568 даёт тот же результат. Захват GDI и X11 — не покрыт.

## 4. Точка входа

`meeting start --screen [<монитор>]`: источник экрана по ОС, проверка монитора и дисплея до каталога встречи;
наблюдение экрана в жизни записи. `meeting replay` ключа не получает.

**Готово, когда:** сборка; отказы `--screen` — до каталога встречи; на Windows — этап 8.

*Подтверждено:* сборка без предупреждений, `meeting start --help` показывает ключ. В WSL отказ звука
(`Audio.NoSoundLibrary`) идёт раньше проверки экрана, поэтому отказ `--screen` запуском здесь не проверить — его
покрывают тесты `ScreenCaptureTests`; каталог встречи при отказе не создан. Число смен в итоге записи — не делалось:
в спеке его нет.

## 5. Стенд и замер правила смены

`prototype/screen-bench` (C#, как `prototype/wnet`): режим «снять» — каждый кадр тем же источником экрана в каталог;
режим «проверить» — то же доменное правило по серии, вывод смен с временем. Серия на экране владельца по шагам:
окно звонка с видео, набор и правка кода в редакторе, смена окна с условием задачи. Числа и условия — в
`docs/measurements.md`; пороги правила правятся только по замеру.

**Готово, когда:** каждая показанная задача и смена окна дают смену, остановки набора дольше 3 с — почти каждая,
ложных от видео — не больше одной в минуту (критерий смягчён решением владельца после замера); замер
воспроизводится стендом.

*Подтверждено:* серия 200 кадров на экране владельца (Windows, 1920×1080), `docs/measurements.md`, «Смена экрана».
Исходное правило — 4 ложные смены от «видео» за полторы минуты. Владелец выбрал память живых ячеек: ячейка, менявшаяся
от 3 раз за 30 с, не считается. С ней — 1 ложная, паузы набора 4 из 5, задача и возврат к коду пойманы. Тесты и 4
мутации памяти — в домене. Страница сценария стартует по щелчку: сам открыть браузер на весь экран агенту не дал
классификатор (закрытие чужих окон Edge).

## 6. Скилл

`meeting-start`/`meeting-mode`: `--screen [N]` доходит до `meeting start`, `--screen-model` (по умолчанию `haiku`) —
в `mode.json`; `--screen` без `--mode` — отказ. Окно подсказок: слежение за `screen.log`, описание фоном
(`--input-format stream-json` с картинкой, свой системный промпт), одна ожидающая смена, блок в `screen.md` только
целиком; `hint-answer` добавляет последнее описание, не `-`; кандидату — подсказка с поводом `задача на экране`
на новый раздел `Задача:`.

**Готово, когда:** тесты скилла (WSL и Git Bash) — все свойства «Скилл» из «Проверяемости» спеки; мутации: снятие
ожидающей смены, подстановка оборванного описания, снятие сравнения раздела `Задача:`, подсказка интервьюеру на
задачу — роняют свои тесты.

*Подтверждено:* 9 тестов окон (`candidate_*Screen*`, `candidate_*Task*`, `candidate_*Description*`,
`interviewer_WhenTaskOnScreen_*`), `start_WhenScreenGiven_*`, `linuxstart_WhenScreenGiven_*`, `--screen-model` в тестах
`mode_*`; 15 мутаций скриптов убиты:
- `screen-describe`: снятие ожидающей смены (описания параллельно), снятие обрыва при выходе, `-` в последнем
  описании, описание промежуточной смены, снятие проверки «модель не ответила», сравнение задачи с пробелами;
- `meeting-candidate`: снятие сравнения задачи, описания во входе, опроса экрана, проверки транскрипта;
- `meeting-interviewer`: описание во входе;
- `meeting-start`: `--screen` на Linux и в Windows;
- `meeting-mode`: `--screen-model`.

Первый прогон мутаций остановил Claude Code из-за нехватки памяти. Мутант, оставшийся в `meeting-candidate`, откачен
по копии. Два выживших (описания параллельно, отказ модели) закрыты тестами, повтор — убиты. Подсказку интервьюеру на
новую задачу проверяет `interviewer_WhenTaskOnScreen_*`: кода, который её давал бы, нет, мутировать нечего.

`SKILL.md`: `--screen`, `--screen-model`, что уходит в Anthropic; правила ролей — экран во входе. README,
`docs/architecture.md` (формат `screen/`, `screen.log`, `screen.md`, сценарий), `docs/decisions.md` (решения спеки),
`docs/pitfalls.md` (что найдётся). Версия плагина поднята.

**Готово, когда:** доки сверены с кодом; `scripts/test.sh` зелёный.

*Подтверждено:* `SKILL.md` (ключи `--screen`, `--screen-model`, отказ без `--mode`, что уходит в Anthropic), README
(раздел «Собеседование: экран», файлы встречи, данные), `docs/architecture.md` («Экран встречи», команда `start`,
данные), `docs/decisions.md`, `docs/pitfalls.md` (GDI на заблокированном экране), `docs/measurements.md` («Смена
экрана»); плагин 0.4.0. Прогон — на закрытии.

## 8. Живая проверка на Windows

По шагам с владельцем, на экране — только тестовая страница: `meeting start --screen` + окно кандидата; условие в
`screen.md` дословно; подсказка `задача на экране` без вопроса; вопрос голосом — подсказка по задаче.

**Готово, когда:** все четыре наблюдения записаны в план.

*Подтверждено (20.11.2026):* сборка ветки `win-x64` во временном каталоге, тестовый корень встреч, страница «условие +
видео» во весь экран, окно кандидата из WSL с настоящим `claude` (Opus — подсказка, Haiku — экран).
- `meeting start --screen` снимает монитор: снимок 1568×882, только тестовая страница.
- В `screen.md` условие задачи дословно, с примером и ограничениями.
- Подсказка `задача на экране` пришла без вопроса: хеш-таблица, O(n), проверка до вставки.
- Вопрос голосом через синтезатор речи в динамики распознан в канале «Собеседники». Подсказки на «Как бы вы решили
  эту задачу» и «Расскажите подход и сложность» — по задаче с экрана.

Время до подсказки отдельно не мерилось.

Найдено и исправлено:
- вторая подсказка `задача на экране` на ту же задачу (описания разошлись пустыми строками) — сравнение без пробелов;
- ошибка `head` в окне, пока транскрипта нет.

Тесты на обе правки добавлены. Ложные смены от «видео» в первые 30 с встречи (память живых ячеек ещё пустая) — 2 за
встречу, безвредны после правки сравнения.

Захват GDI отказывает на заблокированном экране — грабля в `docs/pitfalls.md`, одно предупреждение на серию сбоев
(тест). Linux X11 вживую не проверялся — приёмка #16.

## 9. Закрытие

*Саморевью* (отдельный агент, Opus — по фоновым процессам скрипта и P/Invoke): блокеров нет, `scripts/test.sh`
зелёный, экранные тесты скилла — и в Git Bash. Исправлено:
- экран гасился только после распознавания очереди (после Ctrl+C снимки шли ещё до 30 с) — теперь вместе с подачей
  звука, тест «наблюдение остановлено, пока распознавание висит»;
- три выживших мутанта ревьюера (порядок гашения, кольцо живых ячеек, экран без задачи после задачи) — тесты, повтор
  мутаций — убиты;
- время снимка — по монотонным часам; отказ `--screen 0` — своим текстом; описание не начинается в такте конца
  записи;
- протухшее: структура кода в `docs/architecture.md`, комментарий csproj, отказ без `--mode` в спеке (правило сессии,
  а не скрипта), строка замера «без памяти» — с коммитом.

Оставлено, записано в спеку («Границы»): сбой записи снимка теряет смену, подсказка на реплику обрывает подсказку на
задачу, отказ `--screen` на Linux виден только в окне записи. Не проверено: X11 вживую, несколько мониторов, масштаб
больше 100 %, смена разрешения посреди встречи, правка кода в IDE как вход правила.
