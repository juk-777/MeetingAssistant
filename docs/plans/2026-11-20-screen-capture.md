## 1. Домен

Domain: value object сетки экрана — яркость ячеек 64×36, строится из пикселей RGB снимка любого размера (среднее по
ячейке); правило `ScreenChangePolicy` с константами (порог яркости 4, устоялась 3 с, доля — 5 ячеек, промежуток
10 с) и состоянием наблюдения: опорная сетка, время последнего изменения каждой ячейки, время прошлой смены.
`Observe(сетка, время)` отвечает, сменился ли экран; при смене опорной становится эта сетка.

**Готово, когда:** тесты — все свойства «Домен» из «Проверяемости» спеки; мутации: каждый порог (4 → 5, 5 ячеек →
4, 3 с → 2.9, 10 с → 9.9), снятие «устоялась», опорная — прошлая сетка вместо записанной, первый снимок не смена —
роняют свои тесты.

## 2. Application

Порты: `IScreenSource` (снимок монитора: размер и пиксели RGB), запись смены — файл снимка и строка `screen.log` через
порт хранилища встречи. Сценарий `WatchScreen`: раз в секунду по `TimeProvider` снимок → сетка → правило → при смене
запись; живёт, пока идёт запись встречи, и останавливается вместе с ней; сбой снимка — лог, цикл продолжается. Без
источника экрана цикл не запускается.

**Готово, когда:** тесты на двойниках и `FakeTimeProvider`: смена пишет файл раньше строки (незавершённая задача
двойника), остановка записи останавливает цикл, сбой одного снимка не останавливает ни цикл, ни запись; мутации
порядка «файл раньше строки», снятия остановки и снятия перехвата сбоя роняют свои тесты.

## 3. Infrastructure

`Screen/`: свой PNG (сигнатура, IHDR, IDAT через `ZLibStream`, IEND, CRC-32) и уменьшение до 1568 по длинной
стороне с сохранением пропорций; захват Windows — GDI `BitBlt` монитора по номеру (`EnumDisplayMonitors`, основной —
первым), процесс DPI-aware по мониторам; Linux X11 — `XGetImage` корневого окна через `libX11`, отказы: Wayland, нет
дисплея, нет библиотеки, номер монитора. Хранилище встречи: `screen/<чч-мм-сс>.png` по времени от начала, строка
`<epoch>\t<файл>` в `screen.log`.

**Готово, когда:** тест PNG разбирает файл сам — сигнатура, CRC кусков, пиксели после распаковки; уменьшение —
пропорции и предел; формат `screen.log` и имя файла; захват Windows и X11 тестами не покрыт — подтверждается живым
прогоном (этап 8, Linux — приёмка #16); мутации CRC, фильтра строк и предела уменьшения роняют свои тесты.

## 4. Точка входа

`meeting start --screen [<монитор>]`: источник экрана по ОС, проверка монитора и дисплея до каталога встречи;
`WatchScreen` в жизни записи; итог печатает число смен экрана. `meeting replay` ключа не получает.

**Готово, когда:** сборка, отказы `--screen` на WSL (нет дисплея или Wayland) — до каталога встречи, проверено
запуском; на Windows — этап 8.

## 5. Стенд и замер правила смены

`prototype/screen-bench` (C#, как `prototype/wnet`): режим «снять» — каждый кадр тем же источником экрана в каталог;
режим «проверить» — то же доменное правило по серии, вывод смен с временем. Серия на экране владельца по шагам:
окно звонка с видео, набор и правка кода в редакторе, смена окна с условием задачи. Числа и условия — в
`docs/measurements.md`; пороги правила правятся только по замеру.

**Готово, когда:** каждая показанная задача и каждая остановка набора дольше 3 с дают смену, видео без других
изменений — ни одной; замер воспроизводится стендом.

## 6. Скилл

`meeting-start`/`meeting-mode`: `--screen [N]` доходит до `meeting start`, `--screen-model` (по умолчанию `haiku`) —
в `mode.json`; `--screen` без `--mode` — отказ. Окно подсказок: слежение за `screen.log`, описание фоном
(`--input-format stream-json` с картинкой, свой системный промпт), одна ожидающая смена, блок в `screen.md` только
целиком; `hint-answer` добавляет последнее описание, не `-`; кандидату — подсказка с поводом `задача на экране`
на новый раздел `Задача:`.

**Готово, когда:** тесты скилла (WSL и Git Bash) — все свойства «Скилл» из «Проверяемости» спеки; мутации: снятие
ожидающей смены, подстановка оборванного описания, снятие сравнения раздела `Задача:`, подсказка интервьюеру на
задачу — роняют свои тесты.

## 8. Живая проверка на Windows

По шагам с владельцем, на экране — только тестовая страница: `meeting start --screen` + окно кандидата; условие в
`screen.md` дословно; подсказка `задача на экране` без вопроса; вопрос голосом — подсказка по задаче.

**Готово, когда:** все четыре наблюдения записаны в план с числами (время описания, время до подсказки).
