## 1. Корень встреч скилла из переменной Windows

`meeting-dir`: `MEETINGS_ROOT`, иначе переменная пользователя Windows `Storage__MeetingsRoot` из реестра
(`powershell.exe`, на этапе 1 — `reg.exe`, см. этап 6), иначе отказ с командой установки. `SKILL.md` — по факту.

**Готово, когда:** тесты скилла на двойнике (`reg.exe`, после этапа 6 — `powershell.exe`): `MEETINGS_ROOT` важнее; без него — корень Windows; нет обоих —
отказ. Мутации: порядок источников переставлен; чтение Windows снято — каждую ловит свой тест.

*Подтверждено:* 3 теста, тесты скилла — 30 из 30. Мутации: «реестр раньше `MEETINGS_ROOT`» — тест приоритета;
«чтение реестра снято» — тест корня из реестра. Реестр, а не окружение: окружение WSL не видит переменную,
заданную после его старта. Отсутствие значения (`reg.exe` с кодом 1) под `set -e` обрывало скрипт без текста —
найдено тестом отказа.

## 2. Закрытие окна — как Ctrl+C

Cli: обработчик `SIGHUP` (`CTRL_CLOSE_EVENT`) отменяет запись и ждёт её конца в пределах срока Windows.

**Готово, когда:** сборка и `scripts/inspect.sh` чистые; само поведение — только живым проходом (этап 5).

*Подтверждено:* сборка и инспекция чистые; одно предупреждение (`AccessToDisposedClosure`) заглушено адресно —
регистрация снимается раньше источника отмены. В WSL `SIGHUP` по идущему `replay` — `конец записи`, итог, код 0
(до `context.Cancel` код был 129). `CTRL_CLOSE_EVENT` на Windows — этап 5.

## 3. `/meeting start`

Скилл: скрипт запуска открывает окно `meeting start` (`powershell.exe` → `cmd.exe /c`), ждёт `current.json` с новым `id`,
печатает каталог встречи; `SKILL.md` — команда `start`.

**Готово, когда:** тесты скилла на двойниках `powershell.exe` и `current.json`: новая встреча найдена; прошлая встреча
не принимается за новую; срок вышел — отказ. Мутации: сравнение `id` снято; срок снят — каждую ловит свой тест.

*Подтверждено:* 4 теста, тесты скилла — 34 из 34. Мутации «сравнение `id` снято» и «срок снят» убил тест «прошлая
встреча за новую не сходит» (срок — внешним `timeout` теста). Окно — через `cmd.exe /c … || pause`: при отказе
`meeting` окно ждёт клавишу, и причину видно. `meeting.exe` — по месту установки, переменные установки
перечитываются из реестра: окружение WSL их может не видеть.

## 4. `scripts/install.ps1`

Публикация self-contained `win-x64` в профиль, модели, переменные пользователя, `PATH`; повтор — обновление;
идущая встреча — отказ. README — установка, обновление, удаление.

**Готово, когда:** скрипт проходит на Windows (этап 5).

*Подтверждено:* разбор Windows PowerShell 5.1 без ошибок; файл с BOM — без него 5.1 читает кириллицу в ANSI
(правило — в `.editorconfig`). Прогон — этап 5. README — после приёмки, по пройденным шагам.

## 5. Приёмка на Windows

Критерии 2 и 3 спеки на машине мейнтейнера; размер `app` — в `docs/measurements.md`.

*Подтверждено (12.11.2026):*
- чистый профиль: установка 11 с, `app` 102 МБ; `meeting` по имени из `C:\` с переменными из реестра —
  `replay` фрагмента 180 с, 23 строки, встреча в корне по умолчанию;
- переустановка с `-MeetingsRoot` меняет корень, без параметра — сохраняет; строка `PATH` одна; при идущей встрече —
  отказ с PID;
- `/meeting start стенд-окно` из сессии в WSL: окно `meeting`, сессия подключилась к новой встрече; окно закрыто
  крестиком — блок `конец записи`, 4 строки «Я» распознаны, `audio.wav` 36.0 с читается, процесса не осталось;
- удаление по шагам README — каталога, переменных и строки `PATH` нет, `meeting-dir` отказывает с текстом про
  установку; затем установка заново с корнем мейнтейнера.

Корень встреч в этой сессии задан и `MEETINGS_ROOT` (то же значение); путь через реестр проверен отдельно
с пустым `MEETINGS_ROOT`.

## 6. Закрытие

*Критерии спеки:*
1. `scripts/test.sh` — 176, `scripts/inspect.sh` — 0; свойства `meeting-dir` и `meeting-start` — тесты скилла,
   мутации этапов 1, 3 и саморевью — выживших нет.
2. Чистая установка, запуск из любого каталога, обновление, отказ при идущей встрече — этап 5.
3. `/meeting start` из WSL, закрытие окна — этап 5 и повторный прогон ниже.
4. README и `docs/architecture.md` — по факту; инспекция, саморевью, ретро — здесь.

*Саморевью:* независимый агент (Opus — код обычного радиуса), 176 тестов зелёные. Исправлено:
- корень из реестра читался `reg.exe` — кодовая страница консоли ломала кириллицу, под Git Bash ключ `/v` уходил
  в путь MSYS; теперь `powershell.exe` с выводом в UTF-8, тест на кириллическом корне;
- `/meeting start` ждал встречу в корне `MEETINGS_ROOT`, а окно писало в корень из реестра — окну передаётся корень
  ожидания; тест, мутант «корень не передан» убит;
- мутант «ожидание выключено» выживал — двойник кладёт встречу через 1 с, убит;
- `docs/decisions.md` — решение о корне встреч пересмотрено записью;
- отмена в уже освобождённый CTS из обработчика закрытия окна — перехват, комментарий честный;
- `install.ps1`: `PATH` пользователя — сырым значением того же типа (без раскрытия `%…%`), старый `app` сначала
  переименовывается, модели проверяются по трём файлам, как у приложения;
- имя встречи с `%` или `\` в конце — отказ, тест.

Повторный живой прогон после правок (RDP с перенаправлением звука): без устройств — окно с `Audio.NoDevice` осталось
открытым, `meeting-start` отказал по сроку, прошлую встречу не взял; с устройствами — `/meeting start стенд-2-окно`,
встреча в переданном корне, закрытие окна крестиком — `конец записи`, `audio.wav` 19.8 с. Переустановка поверх —
`PATH` восстановлен, тип значения тот же, `app.old` не остаётся.
