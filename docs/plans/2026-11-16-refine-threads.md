## 1. Настройка

Инфраструктура: настройка в `SpeechOptions`, распознаватель уточнения получает её значение и считает потоки как
меньшее из настройки и половины логических процессоров; значение меньше 1 — отказ `Prepare` с именем настройки до
загрузки модели. Проверка настроек на старте настройку уточнения не проверяет: запись от неё не отказывает.

**Готово, когда:** тесты на число потоков, отказ при 0 и независимость записи зелёные; мутации «снято урезание до
половины», «снята проверка значения», «потоки — по-старому из числа процессоров» роняют свои тесты.

*Подтверждено:* тесты — 330 + 1, 0 упало; мутанты «снято урезание» (3 случая `ThreadsFor`), «снята проверка»
(`Prepare_WhenThreadsBelowOne_…`), «потоки по-старому» (`Threads_WhenSettingBelowHalf…`), «DI не передаёт настройку»
(`Refine_WhenRefineThreadsInvalid_…`) падают на своих тестах; инспекция — 0 предупреждений (на 4 ядрах, `taskset`).

## 2. Замер и умолчание

`prototype/wnet` с `GLUE=1` на `call1`, 4 потока, WSL, как прошлый замер 8 потоков (0.680 к речи). Умолчание 4, если
к речи не больше 1.36 (вдвое дольше 8 потоков); иначе — вопрос владельцу с числами.

**Готово, когда:** число и условия в `docs/measurements.md`; `Speech:RefineThreads` в `appsettings.json`.

*Подтверждено:* 4 потока — 1.027 к речи против 0.680 на 8 (в 1.5 раза дольше, порог 2), CPU 394 %, текст байт в байт
тот же; умолчание 4 — в `appsettings.json`.

## 3. Доки и живая проверка

README (как поменять число потоков), `docs/architecture.md` (настройки, уточнение), `docs/decisions.md` (пункт
«Фоном»). Переменная `Speech__RefineThreads` должна дойти до окна уточнения: в Windows скилл читает переменные
пользователя из реестра (окружение WSL их не видит), на Linux эмулятор с сервером окон не наследует окружения сессии —
значение передаётся аргументом, как корень и модели. Плагин 0.2.13: тег выпуска совпадает с версией плагина.
Вживую на Windows: сборка `win-x64`, `meeting refine` на записи — загрузка процесса около четверти CPU.

**Готово, когда:** доки сверены с кодом; живая проверка записана.

*Подтверждено:* тесты скилла — 117, 0 упало; новый тест `linuxrefine_WhenRefineThreadsInSession_PassesThemToWindow`
(эмулятор без окружения сессии) роняют мутанты «окно не экспортирует переменную» и «значение не передаётся
аргументом». Вживую, нативный Windows: `Speech__RefineThreads=0` — отказ `Speech.RefineThreadsInvalid` с именем
настройки; умолчание — 0.960 к речи на записи 202.6 с, занято ядер медиана 3.9, максимум 4.0 из 16. Не проверено
вживую: чтение переменной пользователя Windows из реестра в `meeting-refine` (двойник `powershell.exe` её не
исполняет) и окно на настоящем Linux.
