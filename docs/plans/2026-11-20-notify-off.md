## 1. Отметка и проверка

`meeting-notify <каталог встречи> <текст>`: нет `<каталог>/notify` — выход 0 без вызова `powershell.exe` и
`notify-send`; нет каталога или аргументов не два — код 2 с подсказкой вызова. `meeting-start`: ключ `--notify`
в любом месте аргументов, после появления новой встречи — пустой `notify` в её каталоге (Windows и Linux), каталог
печатается как раньше. `hint-answer`: `notify` передаёт каталог встречи окна. Тесты скилла — существующие
`notify_*` получают каталог с отметкой; новые: без отметки уведомления нет (заглушки `powershell.exe` и
`notify-send` не вызваны), `start_`/`linuxstart_` с `--notify` ставят отметку и без ключа не ставят, окно кандидата
с отметкой и без.

**Готово, когда:** тесты скилла WSL и Git Bash зелёные; мутации убиты — снятая проверка отметки в `meeting-notify`
(падают тесты «без отметки»), снятая установка отметки в `meeting-start` (падают `start_`/`linuxstart_` с
`--notify`), окно не передаёт каталог (падает тест окна с отметкой).

*Подтверждено:* тесты скилла WSL — 149, Git Bash — 113, 0 упало. Мутации убиты: снятая проверка отметки (падают
`notify_`/`linuxnotify_WhenMeetingHasNoMark_*`, `candidate_WhenMeetingNotifyOff_*`), отметка не ставится и
ставится всегда (падают `start_WhenNotifyGiven_*`, `linuxstart_WhenNotifyGiven_*`), окно передаёт свой рабочий
каталог вместо каталога встречи (падают 2 теста уведомлений кандидата и 1 интервьюера).

## 3. Закрытие

Сверка критериев спеки по списку, живая проверка на Windows (критерий 4): встреча режима кандидата без ключа и
с `--notify`, реплика «Собеседников» голосом TTS — уведомление только во второй. Саморевью, ретро, pull request;
после слияния — тег `v0.4.1`.

*Живая проверка (Windows, WSL, Claude Code 2.1.329, окно кандидата из ветки, `--model haiku`):* приложение записи
слайс не меняет, поэтому встреча синтетическая — `mode.json`, строка «Собеседников» в `transcript.md`, конец записи
в `events.log`; модель и уведомление настоящие. Без отметки `notify` окно ответило, в истории уведомлений Windows
(`ToastNotificationManager.History` приложения PowerShell) — 0; с отметкой — одно уведомление, текст — первая
строка ответа. Голосом TTS через приложение записи не прогонялось: что `meeting-start --notify` ставит отметку
в каталоге встречи, подтверждают тесты `start_`/`linuxstart_WhenNotifyGiven_*`. Уведомление сессии (правило
`SKILL.md`) вживую не проверялось — тот же `meeting-notify`, его ветки закрыты тестами.

*Саморевью (Opus, свежий контекст; правка скриптов скилла обычного радиуса):* блокеров нет, тесты скилла WSL — 149,
0 упало. Исправлено: шапка и схема `docs/architecture.md` и комментарии `meeting-candidate`, `meeting-interviewer`
говорили об уведомлении без условия; длинные строки после переноса. Не проверено вживую: настоящий `notify-send`
на Linux (#16), выполнение правила `SKILL.md` моделью сессии, запуск через приложение записи. Ретро сделано.
