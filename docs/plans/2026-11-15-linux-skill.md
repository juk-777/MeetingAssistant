ОС называет скрипт `platform` по `powershell.exe`: он есть — Windows (WSL и Git Bash), как сейчас; нет и ОС Linux
не в WSL — путь Linux; WSL без `powershell.exe` — отказ (решение владельца 15.11.2026). Тесты Linux идут с `PATH`
без `powershell.exe`; в Git Bash они пропускаются.

## 1. Где стоит приложение

Новый скрипт скилла отвечает, где установка `install.sh` держит корень встреч, каталог моделей и `meeting`. Корень и
модели он читает из блока `meeting-assistant` в `~/.profile`, иначе берёт из окружения. Окружение сессии не видит
блока, дописанного после входа в систему, — как окружение WSL не видит переменной из реестра. `meeting-dir` берёт
корень оттуда же, если нет `MEETINGS_ROOT` и Windows.

**Готово, когда:** тест ставит приложение настоящим `install.sh` в подменённый домашний каталог и сверяет ответы
скрипта с установленным: корень, модели, `meeting`. Мутант «корень только из окружения» падает.

## 2. Окно записи и уточнения

Один скрипт открывает окно эмулятором по списку: `xdg-terminal-exec`, `ptyxis`, `x-terminal-emulator`,
`gnome-terminal`, `konsole`, `xfce4-terminal`, `xterm`. Отказавший на старте пропускается. Список — решения
владельца 15.11.2026, спека, «Окно записи». В окне — `meeting` с корнем и моделями установки, после конца —
ожидание клавиши, как `pause` в Windows. Аргументы идут в окно позиционными параметрами `bash -c`, а не текстом
команды. Ни один не открыл окно — отказ с готовой командой для ручного запуска.
`meeting-start` и `meeting-refine` на Linux открывают окно им; ожидание новой встречи — общее с Windows.

**Готово, когда:** тесты с заглушкой эмулятора: имя встречи с кавычками и `$` доходит до `meeting` как есть,
словарь передан, новая встреча найдена. Нет `meeting` — код 3. Нет эмулятора — отказ с командой. Нет модели Whisper
у уточнения — код 3.

## 3. Сверка версии, установка, уведомление

- `check-app-version` на Linux спрашивает `meeting --version` у установленного; его нет — код 3.
- `meeting-install` качает `install.sh` релиза и запускает его с тем же адресом релизов.
- `meeting-notify` — `notify-send`, без него — ничего, как без `powershell.exe`.

**Готово, когда:** тесты на заглушках `meeting`, `notify-send` и релизе в каталоге зелёные, мутанты падают.

- 16 тестов `linux*_` (кроме `linuxsetup_*` первого pull request) на заглушках `meeting`, эмуляторов,
  `notify-send` и релизе в каталоге. Приложение ставит настоящий `install.sh`.
- Убиты 13 мутантов, каждый своим тестом:
  - корень только из окружения; блок `~/.profile` не читается; корень Linux не ищется;
  - аргументы окна без кавычек; порядок эмуляторов; отказ эмулятора не виден;
  - нет проверки `meeting`, Whisper, установки; словарь не абсолютный;
  - уведомление без `--`, текст обрезан; каталог релиза не берётся.
- Тесты скилла: WSL — 94, Git Bash — 68 и 30 пропущено (Linux и установка ссылкой). `scripts/test.sh` — 287,
  `scripts/inspect.sh` — 0 предупреждений.
- Не проверено живьём: настоящее окно эмулятора и `notify-send`. В WSL их нет, проверка остаётся приёмке.

Саморевью (свежий агент, Opus: bash-скрипты обычного радиуса) нашло блокирующее. В Ubuntu 26.04 с рабочим столом
`x-terminal-emulator` — Ptyxis (`apt-cache show ptyxis`: `Provides: x-terminal-emulator`, ставится задачей
`ubuntu-desktop`), ключа `-e` у него нет, а `gnome-terminal` не стоит. Исправлено решением владельца:
- первым — `xdg-terminal-exec`, он тоже ставится с `ubuntu-desktop`;
- `ptyxis --` в списке;
- эмулятор, отказавший на старте, пропускается.

Исправлено по остальным находкам:
- WSL без `powershell.exe` — отказ, а не путь Linux (решение владельца);
- тесты на эмулятор, живущий с окном, и на незаданный каталог моделей;
- корень и модели окна уточнения закреплены тестом;
- разметка в тексте `notify-send` экранируется;
- тексты кода 3 и подсказка `bzip2` без `apt`.

После правок:
- тесты скилла в WSL — 98;
- убиты 8 новых мутантов: порядок списка, нет перехода к следующему, эмулятор не в фоне, не отвязаны потоки,
  нет отказа в WSL, нет проверки моделей, нет экранирования, корень окна уточнения пуст.
