## 1. Скилл — плагин

`skills/meeting/` переезжает в `plugins/meeting/skills/meeting/`; `plugins/meeting/.claude-plugin/plugin.json`
(версия `0.1.0`), `.claude-plugin/marketplace.json` в корне. Скрипты зовут друг друга и вызываются из `SKILL.md`
через `bash`. `scripts/install-skill.sh`, `scripts/test.sh`, `scripts/slnx-folders.sh` — на новый путь.

**Готово, когда:** тесты скилла зелёные из нового каталога, в том числе со скриптами без бита исполнения;
`claude plugin validate` — без ошибок; скилл, поставленный плагином из рабочей копии, вызывается как `/meeting`.

*Подтверждено:* тесты скилла 34 из 34 — скрипты копией без бита исполнения; мутант «`meeting-start` зовёт
`meeting-dir` напрямую» — 3 теста запуска. `claude plugin validate` — плагин и маркетплейс без ошибок. `claude -p
"/meeting протокол <каталог>"` с плагином из маркетплейса: голый `/meeting` вызвался, `${CLAUDE_SKILL_DIR}`
подставился, скрипты — через `bash`, `protocol.md` записан. Плагин из маркетплейса-каталога читается прямо
из рабочего дерева (переключение ветки его ломает), из маркетплейса GitHub — из своего кеша
(`~/.claude/plugins/cache/<маркетплейс>/<плагин>/<версия>/`).

## 2. `install.ps1`

Без ключей — из релиза (последнего или `-Version`), SHA-256 архива; моделей нет — скачать из релиза sherpa-onnx,
сверить SHA-256, распаковать `tar.exe`. `-FromSource` — сборка из репозитория, как сейчас. Адрес релиза
подменяется для проверки локальным каталогом.

**Готово, когда:** на этой машине: установка из «релиза» в локальном каталоге (архив собран здесь); испорченный
архив — отказ, `app` цел; модели уже есть — не качаются; моделей нет — скачаны и проверены; идущая встреча —
отказ; `-FromSource` — как раньше.

*Подтверждено (Windows этой машины, «релиз» — каталог с архивом, собранным в WSL, `-p:Version=0.1.0-local`):*
- установка с нуля в песочнице (`LOCALAPPDATA` во временном каталоге) — 28 с: архив сверен, модели скачаны из
  релиза sherpa-onnx, сверены, распакованы `tar.exe`; `meeting --version` — `0.1.0-local`; `replay` записи на
  скачанных моделях — 9 строк, как на моделях репозитория;
- повтор — модели не качаются;
- архив с чужой контрольной суммой — отказ «Контрольная сумма … не совпала», `app` цел, версия прежняя;
- `-FromSource` на настоящей установке — сборка, модели из репозитория; переменные пользователя и `PATH` вернулись
  к настоящим путям, строка песочницы из `PATH` убрана руками.

Попутно: сборка без версии показывала умолчание .NET `1.0.0` — теперь `0.0.0-dev` (`Directory.Build.props`).
Отказ при идущей встрече — код не менялся, проверен в #10.

## 3. Скилл ставит `meeting`

`meeting-install` в скриптах скилла запускает установку из релиза через `powershell.exe`; `SKILL.md` — на отказ
«нет `meeting`» предложить установку и по согласию поставить, затем повторить запуск.

**Готово, когда:** тесты скилла на двойнике `powershell.exe`; мутации ловятся.

*Подтверждено:* «не установлено» — код выхода 3 (нет корня встреч в `meeting-dir`, нет `meeting.exe`
в `meeting-start`), скилл реагирует на код, а не на текст. Тесты скилла 38 из 38. Мутации и чем убиты: код 3 из
`meeting-start` не пробрасывается — «приложение не установлено»; `meeting-dir` без корня отдаёт 1 — два теста
«корень не задан»; `meeting-install` глотает код установки — «запуск установки из релиза». `install.ps1` печатает
в UTF-8: из WSL кириллица установки приходила в кодовой странице консоли.
