## 1. Скилл — плагин

`skills/meeting/` переезжает в `plugins/meeting/skills/meeting/`; `plugins/meeting/.claude-plugin/plugin.json`
(версия `0.1.0`), `.claude-plugin/marketplace.json` в корне. Скрипты зовут друг друга и вызываются из `SKILL.md`
через `bash`. `scripts/install-skill.sh`, `scripts/test.sh`, `scripts/slnx-folders.sh` — на новый путь.

**Готово, когда:** тесты скилла зелёные из нового каталога, в том числе со скриптами без бита исполнения;
`claude plugin validate` — без ошибок; скилл, поставленный плагином из рабочей копии, вызывается как `/meeting`.

*Подтверждено:* тесты скилла 34 из 34 — скрипты копией без бита исполнения; мутант «`meeting-start` зовёт
`meeting-dir` напрямую» — 3 теста запуска. `claude plugin validate` — плагин и маркетплейс без ошибок. `claude -p
"/meeting протокол <каталог>"` с плагином из маркетплейса: голый `/meeting` вызвался, `${CLAUDE_SKILL_DIR}`
подставился, скрипты — через `bash`, `protocol.md` записан. Плагин из маркетплейса-каталога читается прямо
из рабочего дерева (переключение ветки его ломает), из маркетплейса GitHub — из своего кеша
(`~/.claude/plugins/cache/<маркетплейс>/<плагин>/<версия>/`).

## 2. `install.ps1`

Без ключей — из релиза (последнего или `-Version`), SHA-256 архива; моделей нет — скачать из релиза sherpa-onnx,
сверить SHA-256, распаковать `tar.exe`. `-FromSource` — сборка из репозитория, как сейчас. Адрес релиза
подменяется для проверки локальным каталогом.

**Готово, когда:** на Windows с WSL: установка из «релиза» в локальном каталоге (архив собран здесь); испорченный
архив — отказ, `app` цел; модели уже есть — не качаются; моделей нет — скачаны и проверены; идущая встреча —
отказ; `-FromSource` — как раньше.

*Подтверждено (нативная Windows с WSL, «релиз» — каталог с архивом, собранным в WSL, `-p:Version=0.1.0-local`):*
- установка с нуля в песочнице (`LOCALAPPDATA` во временном каталоге) — 28 с: архив сверен, модели скачаны из
  релиза sherpa-onnx, сверены, распакованы `tar.exe`; `meeting --version` — `0.1.0-local`; `replay` записи на
  скачанных моделях — 9 строк, как на моделях репозитория;
- повтор — модели не качаются;
- архив с чужой контрольной суммой — отказ «Контрольная сумма … не совпала», `app` цел, версия прежняя;
- `-FromSource` на настоящей установке — сборка, модели из репозитория; переменные пользователя и `PATH` вернулись
  к настоящим путям, строка песочницы из `PATH` убрана руками.

Попутно: сборка без версии показывала умолчание .NET `1.0.0` — теперь `0.0.0-dev` (`Directory.Build.props`).
Отказ при идущей встрече — код не менялся, проверен в #10.

## 3. Скилл ставит `meeting`

`meeting-install` в скриптах скилла запускает установку из релиза через `powershell.exe`; `SKILL.md` — на отказ
«нет `meeting`» предложить установку и по согласию поставить, затем повторить запуск.

**Готово, когда:** тесты скилла на двойнике `powershell.exe`; мутации ловятся.

*Подтверждено:* «не установлено» — код выхода 3 (нет корня встреч в `meeting-dir`, нет `meeting.exe`
в `meeting-start`), скилл реагирует на код, а не на текст. Тесты скилла 38 из 38. Мутации и чем убиты: код 3 из
`meeting-start` не пробрасывается — «приложение не установлено»; `meeting-dir` без корня отдаёт 1 — два теста
«корень не задан»; `meeting-install` глотает код установки — «запуск установки из релиза». `install.ps1` печатает
в UTF-8: из WSL кириллица установки приходила в кодовой странице консоли.

## 4. CI

`.github/workflows/ci.yml` — pull request и `main`: сборка, тесты с моделями из кеша. `release.yml` — тег `v*`:
тесты, сверка тега с версией плагина, сборка `win-x64` с версией, zip, SHA-256, релиз с `install.ps1`.
Проверка `test` (задача workflow `ci`) — обязательна для слияния в `main`.

**Готово, когда:** pull request этой ветки — зелёный прогон на GitHub Actions.

*Подтверждено:* PR #19 — `ci` зелёный, в логе 197 тестов (модели скачаны `scripts/download-models.sh`, кеш
по имени архива); проверка `test` — обязательна для слияния в `main`. Сверка версии выпуска —
`scripts/release-version.sh` с тестами (совпало, разошлось, тег не версия); суммы моделей в `install.ps1`
и `download-models.sh` сверяет тест. Мутации: сравнение версий снято — «версия разошлась»; сумма в одном месте
изменена — тест сверки. Сам `release.yml` — только тегом (этап 6). В WSL нет `bzip2` — `download-models.sh`
распаковывает тогда через Python.

## 5. README

Варианты установки без деления на «пользователя» и «разработчика» (решение мейнтейнера): приложение записи
одной командой из PowerShell или WSL, скилл плагином, из исходников; встреча, обновление, удаление.
`CLAUDE.md`, `AGENTS.md`, `docs/architecture.md`, `docs/development.md`, «Модели» в `docs/measurements.md`
и подсказка приложения при отсутствии моделей — на новые пути.

*Сверх постановки, по решению мейнтейнера:* сборка из исходников двумя путями — `install.ps1 -FromSource`
(PowerShell, без WSL) и `scripts/install-wsl.sh` (сборка в WSL, клон в любом каталоге, .NET в Windows не нужен);
прогон на машине замеров (`docs/measurements.md`) — 22 с, `meeting --version` — `0.0.0-dev`.

*Саморевью* (независимый агент, Opus — код обычного радиуса; 197 тестов, `claude plugin validate` — без ошибок).
Исправлено:
- `--version` дописывал хэш коммита (`0.1.0+…`) — выключено в `Directory.Build.props`; при правке XML-комментарий
  с `--version` сломал весь `Directory.Build.props` (в комментарии XML нельзя `--`) — найдено прогоном
  `install-wsl.sh`, исправлено;
- `.gitattributes` смотрел на старый путь скриптов скилла — CRLF при `core.autocrlf=true`;
- `install.ps1`: модели скачивались после замены `app` — теперь всё скачивается и сверяется до неё, распаковка
  во временный каталог, загрузки убираются и при отказе, кодировка консоли возвращается; проверено в песочнице:
  испорченная сумма модели — отказ, `app` не тронут; текст про сумму архива — «повреждён при загрузке»
  (сумма из того же релиза от подмены не защищает); `-Version 0.1.0` без `v` принимается;
- `meeting-install`: адрес релизов не доходил до `install.ps1` — передаётся `-ReleaseBase`, локальный каталог
  работает; `WSLENV` — тест, мутант «строка снята» убит;
- README: обновление скилла — `claude plugin update`, а не только `marketplace update`; `-UseBasicParsing`;
  почему приложение только для Windows; без диска D:;
- `slnx-folders.sh` не видел вложенный `tests/meeting-skill`;
- `download-models.sh` — распаковка во временный каталог: оборванная не выглядит целой моделью;
- `release.yml`: тег должен стоять на `main`, версия с суффиксом — предварительный релиз;
- решения #14 — в `docs/decisions.md`, выпуск и установка — в `docs/architecture.md` (заодно убрано устаревшее

Обсуждено и оставлено: маркетплейс отдаёт текущий `main`, а не тег (записано в решениях); сумма архива из того же
