## 1. Домен

Domain: value object `SpeechActivity(TimeSpan Position, TimeSpan? SpeakingSince)` — докуда дошёл звук канала и с
какого момента в нём идёт речь (`null` — молчит); константы правила в `AnswerEndPolicy` — `MinAnswer` 10 с,
`SilenceAfterAnswer` 2.5 с, `MinOwnSpeech` 1 с; событие `AnswerEnded(int UtteranceNumber, DateTimeOffset At)`.
`Meeting.Record` фразой «Собеседников» открывает или продлевает ответ (начало первой фразы — конец последней, номер
последней строки). Новый `Meeting.Observe(SpeechActivity me, SpeechActivity others, DateTimeOffset at)` на позиции
`min(me.Position, others.Position)`:
- «Я» говорит не меньше `MinOwnSpeech`, «Собеседники» молчат: ответ от `MinAnswer` — событие; ответ короче — сброс;
- оба молчат, от конца ответа прошло `SilenceAfterAnswer`, ответ от `MinAnswer` — событие;
- «Я» говорит, пока «Собеседники» говорят (эхо, перебивание), — ничего.
После события ответа нет до следующей фразы «Собеседников». `WakePolicy` и счётчик «накопилось» не трогаются.

**Готово, когда:** тесты домена — все свойства «Домен» из «Проверяемости» спеки; мутации: каждый порог (10 → 9.9,
2.5 → 2.4, 1 → 0.9), снятие условия «Собеседники молчат», снятие сброса после события (второе событие на ответ),
промежуток вместо суммы → сумма фраз — роняют свои тесты.

## 2. Конвейер записи

Application: порт `IVoiceActivityDetector` отдаёт `SpeakingSince` (начало идущей речи от начала записи канала) и
`Position`; очередь `MeetingRecorder` несёт не только `RecognizeSpeech`, но и `ObserveSpeech(SpeechActivity Me,
SpeechActivity Others)` — после каждого куска звука, следом за фразами, которые кусок закрыл; обработчик зовёт
`Meeting.Observe` со временем `TimeProvider`; подписчик `AnswerEnded` пишет повод через `IWakeEventWriter`
(`AppendAnswerEnd`). Канал без кусков — позиция 0, событие по нему не наступит раньше подачи звука в оба.
Infrastructure: `SileroVoiceActivityDetector` после каждого окна читает `IsSpeechDetected` и держит начало речи;
`MeetingFiles` пишет `<epoch>\t<номер>\tконец ответа`.

**Готово, когда:** тест Application: речь «Я» начинается до распознавания последней фразы кандидата — строка
транскрипта в файле раньше события (двойник распознавателя с незавершённой задачей); интеграционный тест на
настоящем Silero: `SpeakingSince` ставится на речи и снимается после 0.5 с тишины; мутации: `ObserveSpeech` раньше
фраз куска, `SpeakingSince` всегда `null` — роняют свои тесты.

## 3. Сверка на `replay`, замер

Prototype: `interview_transcript.py` и `interview_truth.py` (замер спеки, разметка по смыслу — локально в
`prototype/out`); `interview_stereo.py` собирает стерео из размеченной записи (I — левый канал, C и M — правый,
вне фраз — тишина) в `samples/`; `interview_replay_check.py` сверяет `events.log` `meeting replay` с концами ответов
разметки. Скрипты разметки кластеризацией (`interview_diarize.py`, `interview_turns.py`, `interview_owner.py`)
удаляются: путь отвергнут, числа спеки из них не берутся. `docs/measurements.md` — раздел «Конец ответа кандидата».

**Готово, когда:** `meeting replay` двух собранных записей (сборка из ветки, WSL) — критерий 4 спеки: не меньше 90 %
чистых концов ответа поймано в пределах 3 с, лишних — не больше 0.2 на ответ; числа — в `docs/measurements.md`.

## 4. Скилл

`meeting-mode` принимает `interviewer`; `candidate-window` становится `hint-window` и открывает окно по режиму;
общая часть окна (вызов `claude` потоком, обрыв, уведомление первой строкой, журнал) выносится из
`meeting-candidate` в подключаемый файл, `meeting-interviewer` — повод из `events.log` (`конец ответа`) и
`marks.log`, ответ кандидата — строки «Собеседников» после последней дописанной подсказки, журнал
`interviewer.md`; `meeting-mark` дописывает `<epoch>` в `marks.log`; `meeting-watch` пропускает `конец ответа`.

**Готово, когда:** тесты скилла (WSL и Git Bash) — свойства «Скилл» из «Проверяемости»; тесты окна кандидата зелёные
без правок; мутации: окно зовёт модель на каждую строку «Собеседников», отметка не обрывает подсказку, оборванная
подсказка сдвигает начало ответа, `meeting-watch` печатает `конец ответа` — роняют свои тесты.

## 5. Правила скилла

`SKILL.md`: режим интервьюера при старте и подключении, поведение сессии (молчит на пробуждения, `оцени` →
`meeting-mark`), текст из чата — вопрос к сессии в любом режиме, протокол интервьюера. Версия плагина — следующая
минорная.

**Готово, когда:** `claude -p "/meeting …"` с `--plugin-dir` на копии встречи: `оцени` в чате даёт вызов
`meeting-mark`, вопрос текстом — ответ; протокол на встрече с `interviewer.md` — разделы спеки.

после концов ответов, уведомление, `оцени` даёт подсказку.

**Готово, когда:** критерий 5 спеки пройден, итог — в этом плане.
