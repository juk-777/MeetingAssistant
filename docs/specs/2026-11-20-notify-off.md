# Подсказки без всплывающих уведомлений

**Статус:** принята 20.11.2026. Issue: #81. Меняет `docs/decisions.md`, «Подсказка доходит системным уведомлением, а не
уведомлением терминала»: уведомление становится включаемым.

## Задача

Первая строка подсказки всплывает системным уведомлением (`meeting-notify`: Windows — `ToastNotificationManager`,
Linux — `notify-send`). Уведомление шлют двое: окно подсказок собеседования (`hint-answer`, первая строка каждого
ответа) и сессия Claude Code по правилам скилла (шаг 1 подсказки — на рабочей встрече и на `обращение`
в режиме собеседования).

На собеседовании кандидата просят показать экран целиком. Уведомление Windows всегда всплывает на основном мониторе
и попадает в показ; выключить его сейчас нельзя. Полный ответ и так виден в окне подсказок и в чате сессии, которые
пользователь держит на непоказанном мониторе, — пользы от уведомления мало, а вред на показе экрана прямой.

## Решения

### Уведомлений по умолчанию нет во всех режимах; включает `--notify` при запуске

`/meeting start <имя> --notify` (и `meeting-start … --notify`) включает уведомления на эту встречу; без ключа их нет
ни на рабочей встрече, ни на собеседовании.

*Почему:* решение владельца (20.11.2026): уведомления почти не нужны, полный ответ виден в окне и в сессии. Одно
правило на все режимы: забытый ключ на собеседовании не выводит подсказку на показанный экран.
*Отвергнуто:* ключ `--no-notify` при включённых по умолчанию (как в тексте issue) — забыл ключ, и подсказка на
показанном экране; выключение только в режиме собеседования — два ключа и правило, зависящее от режима; удалить
уведомления совсем — вернуть их можно было бы только новой задачей.
*Цена:* на рабочей встрече со свёрнутым терминалом подсказку поверх звонка без ключа не видно.

### Включены ли уведомления — отметка в каталоге встречи, проверяет сам `meeting-notify`

`meeting-start` с `--notify` ставит в каталоге новой встречи отметку `notify`. `meeting-notify` принимает каталог
встречи первым аргументом и без отметки ничего не показывает (код 0).

*Почему:* источников уведомления два (окно подсказок и сессия), проверка в одном скрипте закрывает оба. Отметка
лежит во встрече: её видят и окно подсказок, и сессия после переподключения или сжатия контекста — значение не
живёт в памяти модели.
*Отвергнуто:* решать в сессии по аргументам `/meeting` и не звать `meeting-notify` — окно подсказок о ключе не
знает, а сессия теряет его при переподключении; поле в `mode.json` — на рабочей встрече этого файла нет.

## Формат

`<каталог встречи>/notify` — пустой файл: уведомления этой встречи включены. Нет файла — выключены.

`meeting-notify <каталог встречи> <текст>` — вместо `meeting-notify <текст>`.

## Проверяемость

- Без отметки `notify` в каталоге встречи `meeting-notify` не запускает ни `powershell.exe`, ни `notify-send`
  и выходит с кодом 0.
- С отметкой — уведомление как сейчас (текст, склейка строк, экранирование).
- `meeting-start --notify` ставит отметку в каталоге новой встречи, без ключа — не ставит; на Windows и Linux.
- Окно подсказок (кандидат, интервьюер) передаёт `meeting-notify` каталог своей встречи: с отметкой уведомление
  есть, без отметки нет.

## Критерии готовности слайса

1. Тесты скилла (`tests/meeting-skill/run.sh`) зелёные в WSL и в Git Bash, новые проверки свойств выше убиваются
   мутациями: снятая проверка отметки, снятая установка отметки в `meeting-start`, каталог не передан из окна.
2. `SKILL.md`: шаг подсказки зовёт `meeting-notify 'D' '<суть>'`; ключ `--notify` в `start` описан; строка
   пользователю при подключении говорит про уведомление только при `--notify`.
3. README, `docs/architecture.md`, `docs/decisions.md` — умолчание и ключ; версия плагина поднята.
4. Живая проверка на Windows: встреча без ключа — подсказка окна кандидата не всплывает; с `--notify` — всплывает.

## Границы

- Выбор монитора для всплывающей подсказки не делается (решение владельца, нота в #81).
- Включить уведомления у идущей встречи (подключение без `start`, запись, начатая `meeting start` в терминале) —
  только руками: `touch <каталог встречи>/notify`. Ключ у подключения не вводится: сценарий не просили.
- Приложение записи не меняется: уведомления шлёт только скилл.
