# Запись встречи на Linux

**Статус:** принята 14.11.2026, два pull request в одном issue. Issue: #16. Меняет правило проекта «приложение записи — нативный Windows-процесс»
(`CLAUDE.md`, `docs/decisions.md`, «Приложение записи — нативный Windows-процесс на .NET 10»).

## Задача

`meeting start` захватывает звук через WASAPI, поэтому на Linux отказывает: `Audio.CaptureUnsupported`. Всё
остальное работает на Linux и проверяется тестами в Linux: распознавание, файлы встречи, события, скилл. Мешают
два платформенных места:
- захват звука в Infrastructure;
- запуск окна записи, уведомления и установка в скриптах скилла — там зашиты `powershell.exe` и `meeting.exe`.

## Разведка

14.11.2026, WSL (Ubuntu 26.04) с сервером звука WSLg. `libpulse0` скачан `apt-get download` и распакован без
установки, вызовы — из Python через `ctypes`.
- `pa_simple_new` записывает и с `@DEFAULT_SOURCE@` (микрофон по умолчанию), и с `@DEFAULT_MONITOR@` (монитор
  устройства вывода по умолчанию — аналог loopback). Формат задаётся при открытии — s16le, 16 кГц, моно; сервер
  сам переводит частоту.
- Микрофон держит реальный темп: 60 пакетов по 100 мс за 6.15 с, задержка по `pa_simple_get_latency` — 17–21 мс.
- Монитор вывода WSLg отдаёт 6 с тишины за 4.1 с с задержкой 0. Вывод WSLg уходит по RDP. На настоящем Linux
  это нужно проверить при приёмке.

  *Уточнено при реализации:* сервер по умолчанию отдаёт запись кусками около 2 с, и монитор приходит пачками раз
  в 2.04 с. Отсюда «6 с за 4.1 с». С `fragsize` 100 мс ожидание чтения — не больше 0.19 с. При звуке в выводе темп
  монитора реальный (`docs/measurements.md`, «Запись с сервера звука Linux»).

## Решения

### Захват — `libpulse-simple` через P/Invoke

- Вторая реализация `IDeviceStream` — `PulseDeviceStream`:
  - «Я» — `@DEFAULT_SOURCE@`, «Собеседники» — `@DEFAULT_MONITOR@`;
  - формат — s16le 16 кГц моно, остальное делает существующий конвейер;
  - чтение по 100 мс блокирующим `pa_simple_read` в своём потоке;
  - отметка устройства — время прихода минус задержка из `pa_simple_get_latency`;
  - отказ сервера или устройства — `AudioSourceException`, как у WASAPI.
- `LiveCapture` открывает WASAPI на Windows и Pulse на Linux. Нет `libpulse` — отказ до каталога встречи с
  подсказкой, какой пакет поставить. На прочих ОС — `CaptureUnsupported` с новым текстом.

*Почему:*
- Протокол PulseAudio понимают и PulseAudio, и PipeWire (через `pipewire-pulse`, он стоит по умолчанию в
  Ubuntu с 22.10). Одна реализация на оба сервера.
- `libpulse-simple` — пять функций C, без новых пакетов NuGet и без разбора вывода чужой программы.

*Отвергнуто:*
- `parec` или `pw-record` дочерним процессом: зависимость от утилит, которых может не быть, и ещё один процесс,
  который надо гасить.
- Нативный API PipeWire: на PulseAudio без PipeWire не работает.
- Обёртки PortAudio и OpenAL из NuGet: тянут свои нативные библиотеки ради двух потоков записи.

*Цена:*
- Привязка к настоящей `libpulse` проверяется только живым проходом, как и WASAPI: в CI нет сервера звука.
  Сам `PulseDeviceStream` при реализации получил шов на вызовах библиотеки и проверяется тестами на двойнике.
- Имя устройства для человека — «микрофон по умолчанию» и «монитор вывода по умолчанию»: настоящих имён в
  `libpulse-simple` нет.

### Выпуск и установка

- **Выпуск.** `release.yml` собирает ещё и `linux-x64` self-contained: `meeting-linux-x64.tar.gz` с SHA-256.
  Нативные библиотеки sherpa-onnx и Whisper.net приходят из NuGet под RID.
- **Установка — `scripts/install.sh`**, по образцу `install.ps1`:
  - приложение — в `~/.local/share/meeting-assistant`, модели — со сверкой SHA-256;
  - ссылка `meeting` — в `~/.local/bin`;
  - `Storage__MeetingsRoot` и `Speech__ModelsDirectory` — в `~/.profile`;
  - `--from-source` — сборкой из клона (ключи — в духе bash, а не `-FromSource` из `install.ps1`).
- **Правило проекта.** «Нативный Windows-процесс, не WSL» становится «нативный процесс ОС, на которой идёт созвон;
  не WSL». Смысл правила прежний: в WSL нет звука, и памяти мало.

### Скилл на Linux — вторым pull request того же issue

- Скрипты различают Windows (WSL и Git Bash) и Linux. WSL без `powershell.exe` — отказ, а не путь Linux: запись
  там шла бы без системного звука Windows (решение владельца 15.11.2026).
- **Окно записи.** На Linux `meeting start` открывается в эмуляторе терминала по списку: `xdg-terminal-exec`,
  `ptyxis`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `xterm`. Эмулятор, отказавший на
  старте, пропускается. Остановка — Ctrl+C, как на Windows. Ни один не открыл окно — скрипт печатает команду для
  ручного запуска.

  Список меняли дважды 15.11.2026, решения владельца. В принятой спеке были только `x-terminal-emulator` и
  `gnome-terminal`, а это лишь Debian, Ubuntu до 24.04 и GNOME. Затем ревью нашло, что в Ubuntu 26.04
  `x-terminal-emulator` — Ptyxis без ключа `-e`, а `gnome-terminal` не стоит. Поэтому первым идёт
  `xdg-terminal-exec` — терминал, выбранный в системе.
- **Уведомление** — `notify-send`.
- **Установка** — `install.sh`.
- **Сверка версии** — `meeting --version`.

*Почему двумя pull request:* приложение на Linux можно принять отдельно, запуская `meeting start` руками. Скилл
меняет другой набор файлов и тестов, а откатываются они независимо.

## Проверяемость

- Выбор захвата по ОС и отказ без `libpulse` — тесты на шве. Сама `libpulse` в тестах подменена.
- `PulseDeviceStream` — живой прогон в WSL на WSLg с распакованной `libpulse`: встреча пишется, фразы
  распознаются.
- `install.sh` — тест в духе тестов `install.ps1`: сверка сумм и раскладка в подменённом домашнем каталоге.
- Тесты всего решения зелёные в WSL и в CI.

## Критерии готовности слайса

- **Первый pull request:**
  - `meeting start` в WSL с WSLg пишет встречу с микрофона, монитор не роняет запись;
  - выпуск собирает архив `linux-x64`;
  - `install.sh` ставит приложение;
  - доки: README, вариант «Ubuntu»; `docs/architecture.md`; `docs/decisions.md`; правило в `CLAUDE.md` и
    `AGENTS.md`;
  - плагин — новая версия, тег после слияния: `install.sh` и архив едут в релиз.
- **Второй pull request:** скилл на Linux, тесты скилла в WSL, Git Bash и на подменённом Linux, новая версия
  плагина.
- **Приёмка** — человек с Ubuntu и настоящими устройствами:
  - установка одной командой;
  - созвон в наушниках, оба канала пишутся;
  - темп монитора вывода — тот риск, что виден на WSLg.

  Issue закрывается после приёмки.
