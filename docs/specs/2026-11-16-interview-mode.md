# Режим собеседования, слайс 1: роль кандидата с быстрой подсказкой

**Статус:** черновик. Issue: #11. Захват экрана — #57, не здесь.

## Задача

У `/meeting` один режим — рабочая встреча: сессия проекта просыпается на вопрос, термин, обращение и минуту речи и
отвечает фактом из кода или общим знанием. На собеседовании, где «Я» — кандидат, этого мало:
- подсказка приходит через 9.6 с после события (медиана по 37 подсказкам, p90 — 12.6 с; Opus, effort high;
  `docs/measurements.md`, «Скилл `/meeting` на записях созвонов»), а интервьюер ждёт ответа сразу;
- задание интервьюера часто звучит без «?» («Расскажите о своём опыте с Kafka.») — правило `вопрос` его не ловит;
- знание — резюме и заметки кандидата, а не код проекта.

Рамка владельца (ноты в #11): две роли, обе с живыми подсказками по транскрипту, источник — звук встречи и файлы на
входе. Предупреждать ли другую сторону о записи, решает пользователь. Решения владельца по исследованию
(16.11.2026): быстрый путь потоком вместе с сессией; первой — роль кандидата; модель быстрого пути — настройкой,
по умолчанию Opus. Роль интервьюера — следующим слайсом, когда появится запись собеседования для замера порога
«конец ответа кандидата».

## Что есть на рынке

- **Сторона интервьюера** — «interview intelligence» (Eightfold, Joveo, Convo): подсказки по ходу, уточняющие
  вопросы, оценка по компетенциям, протокол. Исследование подсказок интервьюеру (arXiv 2602.20891): подсказка помогает,
  но отнимает внимание.
- **Сторона кандидата** — «interview copilots» (Cluely, Interview Coder, Final Round AI и др.). Главное, что продают,
  — ответ в первые секунды после вопроса.

## Почему не правила для той же сессии

Задержку подсказки задаёт ход модели в агентской сессии: доставка события — 0.5 с, распознавание фразы — до 1.4 с,
остальное — модель. Отдельный короткий вызов модели с ответом потоком (`prototype/fast_hint.sh`: `claude -p` без
инструментов, MCP, настроек и сессии; Claude Code 2.1.325, effort low, WSL, синтетический вопрос по системному
дизайну, по 5 прогонов, 16.11.2026):

| Модель | Первый текст, мин–макс (медиана) | Ответ целиком, мин–макс (медиана) |
|---|---|---|
| Haiku | 1.2–3.3 с (1.4) | 4.2–6.4 с (4.7) |
| Sonnet | 1.4–2.5 с (1.9) | 7.1–9.4 с (8.8) |
| Opus | 1.3–2.3 с (1.6) | 6.3–7.4 с (6.6) |

Первая строка потоком появляется через 1.3–2 с после вызова у любой модели. От конца реплики до первой строки —
около 3–4 с: 0.5 с тишины, по которой VAD закрывает фразу, до 1.4 с распознавания, 1.3–2 с модели. Это оценка по
частям; путь целиком меряется в этом слайсе.

## Решения

### Режим выбирается при старте и записывается во встречу

`/meeting start <имя> [словарь] --mode candidate [--context '<строка>'] [--notes <файл>]…`. Скилл пишет режим,
контекст и пути заметок в `mode.json` каталога встречи: сессия, подключившаяся заново, читает режим оттуда.
Без `--mode` — рабочая встреча, как сейчас.

- *Почему:* режим — свойство встречи, а не сессии; переподключение не должно его терять.

### Быстрый путь — по каждой реплике «Собеседников», а не по событию

Скрипт `meeting-candidate` следит за транскриптом встречи (опросом, как `meeting-watch`). На каждую новую строку
«Собеседники» от 3 слов он зовёт `claude -p` с ответом потоком:
- модель — из настройки, по умолчанию `opus`, effort `low`;
- запуск без инструментов, MCP, настроек и сохранения сессии (как в `fast_hint.sh`);
- на входе — роль, контекст, заметки (резюме, о компании), последние строки транскрипта и сама реплика;
- ответ — первая строка суть, дальше 3–4 коротких тезиса, или `-`, если отвечать не на что (реплика —
  не вопрос и не задание).

Новая реплика «Собеседников» обрывает недописанный ответ на прошлую: интервьюер продолжил или переформулировал, и
прошлый ответ устарел.

- *Почему:* задание без «?» правило `вопрос` не ловит, а решить «вопрос или нет» по одной фразе модель умеет
  лучше правила. Вызов на каждую реплику дороже по токенам, но реплик «Собеседников» на собеседовании — единицы в
  минуту.
- *Отвергнуто:* по событию `вопрос` — теряет задания без «?»; новое правило в приложении — то же решение, только
  жёстче и с выпуском приложения.

### Ответ — потоком в своё окно и первой строкой в уведомление

`meeting-candidate` работает в своём окне, открытом скиллом так же, как окно записи: Windows — через `powershell.exe`
(из WSL — окно с `wsl.exe` в том же дистрибутиве), Linux — эмулятор терминала, как `linux-window`. Ответ печатается
по мере прихода. Когда дописана первая строка, она уходит во всплывающее уведомление (`meeting-notify`): на
собеседовании в фокусе окно звонка. Каждый ответ пишется в `candidate.md` каталога встречи: таймкод реплики, реплика,
ответ.

- *Почему:* уведомление видно поверх звонка; окно держит ответ целиком, пока его читают.

### Сессия в режиме кандидата на реплики не отвечает

Сессия `/meeting` подключается как обычно. В режиме кандидата на пробуждения она молчит, если быстрый путь уже
ответил: подсказок не дублирует. Отвечает на обращение «агент» и пишет протокол.

### Протокол кандидата

`протокол` в режиме кандидата: какие вопросы задали (таймкоды), где ответ вышел слабым, что подготовить к следующему
этапу, что узнал о компании. Источник — транскрипт и `candidate.md`.

## Формат

`mode.json` в каталоге встречи:

```
{"mode": "candidate", "context": "собеседование по бэкенду, системный дизайн", "notes": ["/путь/резюме.md"], "model": "opus"}
```

`candidate.md` — блок на реплику: `## [чч:мм:сс] <реплика>`, под ним ответ. Ответ `-` — строка `(нет ответа)`.

## Проверяемость

- Реплика «Собеседников» без «?» («Расскажите о …») даёт вызов модели; реплика «Я» — нет; реплика короче 3 слов — нет.
- Новая реплика «Собеседников» обрывает недописанный ответ.
- Первая дописанная строка ответа уходит в уведомление один раз.
- Режим переживает переподключение сессии: читается из `mode.json`.
- Без `--mode` поведение скилла прежнее.

Тесты скилла — двойником `claude` (скрипт, печатающий заданный поток с паузами), как в `tests/meeting-skill/`.

## Критерии готовности слайса

1. Тесты скилла на `meeting-candidate` и разбор `--mode` — зелёные в WSL и Git Bash; мутации снятия фильтра
   канала, обрыва прошлого ответа и уведомления роняют свои тесты.
2. Задержка целиком — от строки «Собеседники» в транскрипте до первого текста в окне — замерена на стенде
   `prototype/meeting-feed.sh` со сценарием собеседования (синтетический текст), с моделью и effort явно; число — в
   `docs/measurements.md`.
3. Живая проверка: `meeting replay` записи с репликами в роли интервьюера (запись делает владелец или синтетическая
   речь), окно открывается, ответы идут, уведомление показывается.
4. `SKILL.md`, README, `docs/architecture.md`, `docs/decisions.md` описывают режим; версия плагина поднята.
5. `scripts/test.sh` зелёный.

## Границы

- Роль интервьюера, правило «конец ответа кандидата» — следующий слайс.
- Захват экрана — #57.
- Приложение записи не меняется: фильтр канала и вызов модели — в скрипте скилла.
- Качество ответов разных моделей не сравнивается: модель выбирает пользователь.
- Claude Code для Windows (Git Bash) — окно через `powershell.exe`, как окно записи; macOS — нет (#32).
