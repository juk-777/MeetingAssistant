# Скилл `/meeting`: пробуждение по событиям и подсказки

**Статус:** принята 10.11.2026. Issue: #2. Уточняет `docs/architecture.md`, раздел 2: истечение `Monitor`, кто дочитывает
транскрипт.

## Задача

Приложение пишет `transcript.md` и `events.log`, но их никто не читает: подсказок на встрече нет. Нужен скилл,
который подключает рабочую сессию проекта к идущей встрече. Сессия просыпается по событию, видит всё сказанное
с прошлого пробуждения и отвечает подсказкой с источником или молчит. После встречи она по транскрипту делает
протокол.

Обкатывается скилл на `meeting replay` (#7): записи созвона и Windows-процесс записи уже есть, живого захвата
(#8) для этого не нужно.

## Решения

### Скилл версионируется в репозитории и ставится ссылкой

Исходник — `skills/meeting/` в репозитории:
- `SKILL.md` — правила для сессии;
- `scripts/` — скрипты, которые сессия вызывает.

`scripts/install-skill.sh` создаёт символическую ссылку `~/.claude/skills/meeting` на этот каталог.

- *Почему:* скилл — часть продукта, его правят вместе с форматами файлов, ревьюят и тестируют. По ссылке
  обновление репозитория сразу меняет скилл, отдельно его обновлять не нужно.
- *Отвергнуто:* копия при установке — устаревает молча. Скилл только в `~/.claude` — без ревью, тестов
  и истории, а в публичном репозитории его не увидит никто.

### Корень встреч — переменная окружения `MEETINGS_ROOT`

Скилл берёт `current.json` из `$MEETINGS_ROOT`. Значение — тот же корень, что `Storage:MeetingsRoot` приложения.
Задаётся в `env` пользовательского `~/.claude/settings.json`, в репозиторий не попадает.

Вызов `/meeting <каталог>` подключает сессию к каталогу встречи напрямую, без `current.json`.

`directory` из `current.json` — путь процесса записи. Если это путь Windows (`D:\…`), а сессия в WSL, он
переводится через `wslpath -u`.

- *Почему:* корень — настройка машины, как пути моделей у приложения. `env` в настройках Claude Code
  видят и скрипты скилла, и `Monitor`.
- *Отвергнуто:* корень аргументом при каждом вызове — его пришлось бы помнить и набирать на каждой встрече.

### `Monitor` отдаёт сессии событие вместе с новыми строками транскрипта

`Monitor` запускает `scripts/meeting-watch <каталог>`. Скрипт следит за `events.log` и на каждое событие печатает
одним блоком:
- заголовок: время события, поводы, номер строки;
- все строки транскрипта, которые прочитаны впервые.

Каждая строка печатается как `[чч:мм:сс] Я|Собеседники: текст`.

Состояние чтения хранит сам скрипт, в `${XDG_STATE_HOME:-~/.local/state}/meeting-assistant/`. Для каждой пары
«каталог встречи, проект сессии» в нём два числа: сколько событий отдано и до какой строки прочитан транскрипт.

- *Почему:*
  - сессия получает текст прямо в уведомлении и не тратит на чтение отдельный вызов инструмента — это секунды
    задержки на каждое событие;
  - номер прочитанной строки не теряется при сжатии контекста;
  - две сессии разных проектов на одной встрече читают независимо.
- *Отвергнуто:*
  - `tail -F` в `Monitor` и чтение транскрипта отдельным скриптом, как в прототипе (`prototype/delta.sh`).
    Это лишний вызов на каждое событие и смещение в каталоге встречи, общее для всех сессий;
  - команда `meeting read` в приложении — скиллу пришлось бы знать путь до исполняемого файла, а из WSL это
    ещё и Windows-процесс;
  - номер прочитанной строки в памяти модели — теряется при сжатии контекста.

### Перезапуск `Monitor` без потерь и повторов

`Monitor` живёт не больше 30 минут, по истечении сессия получает уведомление и перезапускает его. Так же
перезапускается `Monitor`, остановленный по любой другой причине, кроме `конец записи`. Скрипт продолжает
с сохранённого состояния, поэтому события, пришедшие в промежутке, не теряются и не повторяются.

На `конец записи` скрипт отдаёт оставшиеся строки и выходит сам. Сессия больше не перезапускает `Monitor`
и предлагает протокол.

Первое подключение к идущей встрече отдаёт весь транскрипт до этого момента одним блоком: сессия получает
контекст начала встречи. Прошлые события при этом не повторяются.

- *Почему:* в `docs/architecture.md` сказано, что `Monitor` истекает молча. Описание инструмента говорит другое:
  по истечении приходит уведомление с числом событий. На это и опирается перезапуск; живой прогон проверяет его.

### Подсказка: 2–3 строки с источником или молчание

Правила `SKILL.md` для пробуждения:
- Подсказка — 2–3 строки: суть и источник (`файл:строка`, issue, документ). Без источника подсказки нет.
- Сказать нечего — молчание. Ход кончается без текста подсказки.
- Подсказка дублируется уведомлением: на созвоне терминал не на виду. Основной канал — уведомление Windows
  (`scripts/meeting-notify` через `powershell.exe`): оно не зависит от терминала. Уведомление терминала,
  которое шлёт `PushNotification`, Windows Terminal на прогоне не показал; `PushNotification` остаётся ради
  телефона при подключённом Remote Control. При открытом терминале инструмент сам пропускает уведомление.
- Во время встречи — только чтение. Не коммитить, не пушить, не писать в issue, чаты и другие внешние системы.
- Исключение одно: просьба на встрече «отправь в <проект>: …». Задача уходит через `SendMessage` в сессию того
  проекта, сессию находит `ListAgents`. Сессии нет — подсказка об этом, задача не теряется молча.

### Каждое пробуждение пишется в `hints.md`

`scripts/meeting-hint` дописывает в `hints.md` каталога встречи строку на каждое пробуждение — и с подсказкой,
и с молчанием.

- *Почему:* по этому файлу считаются задержка «событие → подсказка» и доля молчаний. Оба числа нужны для настройки
  событий (#3). Позже из этого же файла читает окно подсказок.
- *Цена:* лишний вызов инструмента на пробуждение. Он идёт после текста подсказки в терминале, поэтому подсказку
  не задерживает; у подсказки он один с `meeting-notify`.

### Протокол — по команде, файлом в каталоге встречи

`/meeting протокол [каталог]` читает транскрипт целиком (по умолчанию — встреча из `current.json`) и пишет
`protocol.md` в каталог встречи:
- темы;
- решения;
- задачи (что, кто, срок — как прозвучало);
- открытые вопросы.

Спорные места («кто делает», «кому перезвонить») разбираются по таймкоду с вариантами, без обобщения
до одного вывода. «Кто» — Я / Собеседники или имя, если оно прозвучало: разметки говорящих нет.

- *Почему:* протокол — большой ход модели по всему транскрипту, он нужен не после каждой встречи. Файл остаётся
  локально рядом с транскриптом.

### Скрипты — bash, тесты — bash в общем прогоне

Скрипты используют `bash`, `awk`, `jq` и `wslpath`, если он есть. Тесты скриптов — bash-сценарии
на синтетических файлах встречи во временном каталоге. `scripts/test.sh` запускает их вместе с тестовыми
приложениями .NET.

- *Отвергнуто:* тесты из xUnit через запуск `bash` — та же проверка, но с лишним слоем, и под Windows
  без bash они не идут.

## Формат

Вывод `meeting-watch` на событие (поля заголовка через табуляцию):

```
событие\t1762774261.481\tвопрос,термин\t12
[00:03:01] Я: …
[00:03:07] Собеседники: …
```

Первое подключение — заголовок `начало\t<строк>` и все строки транскрипта. Конец — заголовок
`конец записи\t<epoch>\t<номер>` и оставшиеся строки.

`hints.md` — строка на пробуждение, поля через табуляцию:

```
<epoch события>\t<epoch записи>\t<номер строки события>\t<текст подсказки или ->
```

Непустые строки подсказки склеиваются через ` / `, табуляции заменяются пробелом, `\r` убирается. `-` — молчание.

## Проверяемость

- Каждая строка транскрипта отдаётся сессии ровно один раз: без пропусков и повторов. Это верно при перезапуске
  `meeting-watch` между событиями, в том числе после того, как строка записана, а её событие ещё нет. Состояние
  сохраняется после вывода блока: если процесс убит ровно между выводом и сохранением, блок повторится, но не
  потеряется.
- Строка, которую процесс записи ещё не дописал до перевода строки, не отдаётся. Она уходит со следующим событием.
- Событие, записанное, пока `meeting-watch` не работал, отдаётся при перезапуске.
- `конец записи` завершает `meeting-watch` с кодом 0. Перезапуск после конца печатает только заголовок конца
  и снова выходит: все строки уже отданы вместе с ним.
- Пути из `current.json`:
  - путь Windows из WSL переводится;
  - путь POSIX берётся как есть;
  - нет `current.json` или `MEETINGS_ROOT` — отказ с текстом, что задать.
- Состояния двух проектов на одной встрече независимы.
- `hints.md`: одна строка на вызов, многострочный текст склеен, молчание — `-`.

## Критерии готовности слайса

1. Тесты скриптов зелёные в `scripts/test.sh`. Мутации скриптов убиты:
   - снят учёт отданных событий;
   - неполная строка отдаётся;
   - выход на конце снят;
   - перевод пути снят.
2. Живой прогон:
   - `meeting replay` записи созвона идёт Windows-процессом с корнем встреч на диске Windows;
   - сессия в WSL открыта отдельно, в другом проекте, и подключается `/meeting` с чистого листа;
   - перезапуск проверяется на коротком сроке: для прогона `Monitor` ставится на 3 минуты, это 3–4 перезапуска
     за запись.

   По итогам `hints.md` и `transcript.md`:
   - на каждое событие `events.log` после подключения есть строка в `hints.md`; события до подключения приходят
     блоком `начало`, на него сессия не отвечает;
   - сессия получила все строки транскрипта (сверка по номерам);
   - на `конец записи` `Monitor` не перезапущен;
   - задержка «событие → подсказка» (p50, max) и доля молчаний записаны в `docs/measurements.md` с условиями;
     медиана — не больше 15 с, как у прототипа.
3. `/meeting протокол` на той же записи пишет `protocol.md` со всеми четырьмя разделами.
4. `scripts/install-skill.sh` на чистом `~/.claude/skills` ставит ссылку, повторный запуск ничего не ломает.
5. `docs/architecture.md`, раздел 2, описывает фактическое поведение: истечение `Monitor` с уведомлением,
   новые строки в уведомлении, `hints.md`, протокол.

Транскрипт и подсказки живого прогона в репозиторий, issue и чат не выносятся — только числа.

## Границы

- Живого захвата нет: прогон идёт на `meeting replay`. Подсказки на настоящем созвоне — после #8.
- Правила событий не меняются. Число событий и доля молчаний — вход для #3.
- Окна подсказок нет: `hints.md` пишется, но его читатель — отдельная часть (раздел 3 архитектуры).
- Словарь встречи по-прежнему задаётся приложению (`--glossary`), скилл его не ведёт.
- Claude Code под Windows без WSL (Git Bash) не проверяется.
