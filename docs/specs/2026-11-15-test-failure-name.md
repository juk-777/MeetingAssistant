# Имя упавшего тестового приложения в `scripts/test.sh`

**Статус:** принята 15.11.2026. Issue: #44.

## Задача

`scripts/test.sh` гоняет тестовые приложения по очереди. Упавшее приложение он засчитывает: итоговый код — 1. Но
печатает при этом только его вывод. Тестовое приложение, упавшее нативно (например, sherpa-onnx на неверном файле
модели), вывода почти не оставляет. В логе остаётся пустая строка, и не видно, какое из четырёх приложений упало и
с каким кодом. То же у тестов скилла: при отказе печатается только их вывод.

## Решения

### Перед выводом упавшего — строка с именем и кодом

`FAIL  <приложение> — код <код>` перед его выводом, в том же виде, что строки `ok` и `--`. Так же для тестов скилла:
`FAIL  скилл /meeting — код <код>`. Тесты скилла, вышедшие с кодом 0 без строки итога, тоже засчитываются упавшими —
к коду добавляется «нет строки «итого»», иначе строка `FAIL … — код 0` читается как противоречие.

*Почему:* строка с именем не зависит от того, что успело напечатать само приложение.

## Проверяемость

Автотеста нет: `scripts/test.sh` собирает решение и гоняет все приложения. Обвязка ради двух строк — несоразмерна.
Проверка — живым прогоном, как в issue: подменить распознавателю GigaAM файл модели неверным и запустить
`scripts/test.sh`. В issue подменялся путь joiner у RNNT, но RNNT снят, а у CTC файл модели один.

## Критерии готовности слайса

- Прогон с подменённым путём печатает `FAIL  MeetingAssistant.Infrastructure.IntegrationTests — код <N>` и выходит
  с кодом 1.
- Прогон без подмены — как раньше: строки `ok`, итог.
- Тесты скилла, упавшие (подменой проверки), печатают `FAIL  скилл /meeting — код <N>`.

## Границы

Что именно упало внутри приложения (какой тест), по-прежнему видно только из его вывода.
