# Имя упавшего тестового приложения в `scripts/test.sh`

**Статус:** принята 15.11.2026. Issue: #44.

## Задача

`scripts/test.sh` гоняет тестовые приложения по очереди. Упавшее приложение он засчитывает: итоговый код — 1. Но
печатает при этом только его вывод. В #39 тестовое приложение упало нативно (декодеру GigaAM подставили путь joiner
у RNNT) и вывода не оставило: в логе осталась пустая строка, и не было видно, какое из четырёх приложений упало и с
каким кодом. То же у тестов скилла: при отказе печатается только их вывод.

## Решения

### Перед выводом упавшего — строка с именем и кодом

`FAIL  <приложение> — код <код>` перед его выводом, в том же виде, что строки `ok` и `--`. Так же для тестов скилла:
`FAIL  скилл /meeting — код <код>`. Тесты скилла без строки итога засчитываются упавшими при любом коде, как и
раньше; к коду тогда добавляется «нет строки «итого»», иначе строка `FAIL … — код 0` читается как противоречие.

*Почему:* строка с именем не зависит от того, что успело напечатать само приложение.

## Проверяемость

Автотеста нет: `scripts/test.sh` собирает решение и гоняет все приложения, обвязка ради строки вывода несоразмерна.
Проверка — живым прогоном `scripts/test.sh` с подменой. Способ из issue (путь joiner у RNNT) больше не годится: RNNT
снят, у CTC файл модели один. Файл модели GigaAM, подменённый мусором, даёт не нативный обрыв, а обычное падение
тестов (код 2) с выводом. Строка `FAIL` от вывода не зависит, поэтому для проверки этого хватает.

## Критерии готовности слайса

- Прогон с файлом модели GigaAM, подменённым мусором, печатает
  `FAIL  MeetingAssistant.Infrastructure.IntegrationTests — код <N>` и выходит с кодом 1.
- Тесты скилла, упавшие (подменой скрипта скилла), печатают `FAIL  скилл /meeting — код <N>`.
- Тесты скилла без строки итога печатают `FAIL  скилл /meeting — код <N>, нет строки «итого»`, итоговый код — 1.
- Прогон без подмены — как раньше: строки `ok`, итог.

## Границы

- Что именно упало внутри приложения (какой тест), по-прежнему видно только из его вывода.
- Код нативного обрыва печатается числом, как его отдаёт оболочка (`код 134` — сигнал 6), без названия сигнала.
- Приложение .NET с кодом 0 без строки `total:` засчитывается как `ok … — 0` — так было и до правки, не
  разбиралось.
