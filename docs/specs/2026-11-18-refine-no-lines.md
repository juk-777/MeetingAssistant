# Уточнение без единой строки Whisper — отказ

**Статус:** принята 18.11.2026 (владелец: «делай 71»). Issue: #71.

## Задача

`meeting refine` пишет `transcript.whisper.md` и выходит с кодом 0, даже если Whisper не дал ни одной строки:
`RefineMeetingHandler` завершает черновик и отвечает успехом без проверки числа строк. В окне только итог «Строк 0;
речь N с …». `/meeting протокол` берёт пустой файл как второй транскрипт и сводит GigaAM с пустотой.

## Решения

### Ни одной строки — отказ, черновик бросается

Уточнение, после которого строк нет, отвечает отказом `Refine.NothingRecognized`: «Whisper не распознал ни одной
фразы (речь N с): transcript.whisper.md не записан, прежний не тронут.» N — секунды речи целым числом, культура
инвариантная. Ошибка — в `MeetingScenarioErrors` (код константой, текст — методом с речью), как
`AudioSourceFailed`. Проверка — в `RefineMeetingHandler` после распознавания, до записи строк в черновик; число строк
и речь отдаёт `Refinement`. Черновик освобождается без `Complete` — `.part` удаляется, прежний готовый транскрипт
остаётся (`RefinedTranscriptFiles`, так же при исключении и отмене посреди уточнения). Код выхода — 1, как у
остальных отказов; окно печатает `Refine.NothingRecognized: …` вместо итога «Строк …» (`MeetingHost.Exit`).

- *Почему:* пустой файл выдаёт себя за результат — протокол и человек принимают его за «Whisper ничего не
  услышал», хотя речь была. Отказ виден в окне, и повтор можно запускать сразу.
- *Моё решение:* отказ и при записи без речи (речь 0 с) — тот же код, в тексте «речь 0 с». Второй транскрипт пустой
  записи ничего не даёт протоколу, отдельная ветка — лишнее правило.

### Протокол не считает пустой `transcript.whisper.md` вторым транскриптом

`SKILL.md`, «Протокол»: пустой `transcript.whisper.md` (ни одной строки — так их и писали прежние версии) — как
его нет, во всех местах раздела: шаг 2, строка «Транскрипты» и раздел расхождений, правило `.part` (пустой итоговый и
`.part` — уточнение ещё идёт). Так протокол не сводит GigaAM с пустотой и на файлах, записанных до этого исправления.
Читатель файла один — модель по правилам скилла; код его только пишет. Версия плагина — 0.3.1: до тега
`v0.3.1` скилл отвечает кодом 4 на приложение 0.3.0 — штатно, тег сразу после слияния.

## Проверяемость

Application:
- распознаватель отдаёт только пустые отрезки при речи в записи — отказ `Refine.NothingRecognized`, черновик не
  завершён, строк не записано;
- в записи нет речи (одни паузы) — тот же отказ, распознаватель не вызван;
- есть хоть одна строка — успех, черновик завершён (существующие тесты).

Скилл: правило протокола — живой прогон `/meeting протокол` на копии встречи с пустым `transcript.whisper.md`.

## Критерии готовности слайса

1. Тесты Application на отказ — зелёные; мутации «снята проверка числа строк» и «отказ только при речи» роняют
   свои тесты.
2. Живой `meeting refine` (сборка из ветки в WSL, модель Whisper из `models/`) на синтетической встрече в scratchpad:
   `audio.wav` — 10 с тишины, пустой `transcript.md`, `events.log` с `конец записи`. Код 1, строка
   `Refine.NothingRecognized: …`, в каталоге нет ни `transcript.whisper.md`, ни `.part`.
3. `/meeting протокол` (`claude -p`, скилл из ветки) на синтетической встрече в scratchpad: несколько строк
   `transcript.md` и пустой `transcript.whisper.md` — протокол без строки «Транскрипты» и раздела расхождений.
4. `scripts/test.sh` зелёный, инспекция — 0 предупреждений; README и `docs/architecture.md` описывают отказ и
   правило протокола; плагин 0.3.1, тег — после слияния.

## Границы

- `.part` от уточнения, которое упало или было закрыто, протокол по-прежнему читает как «уточнение ещё идёт»:
  признака мёртвого процесса нет. Отдельный вопрос, не этот слайс.
- Порог «слишком мало строк на речь» (Whisper распознал кусок, а не всю встречу) не вводится.
