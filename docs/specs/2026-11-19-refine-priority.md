# Уточнение с уже пониженным приоритетом не падает

**Статус:** принята 19.11.2026. Issue: #76.

## Задача

`meeting refine` ставит процессу приоритет «ниже среднего». На Linux процесс, запущенный с приоритетом ниже
(`nice -n 19`), без прав поднять его не может: `Process.PriorityClass` бросает `Win32Exception (13): Permission
denied`, исключение не обработано, уточнение падает до начала работы.

## Решения

Отказ установить приоритет — не ошибка уточнения: `RefineCommand` ловит `Win32Exception` и идёт дальше с тем
приоритетом, что есть. На Linux отказ `setpriority` без прав значит, что текущий приоритет уже ниже запрошенного,
то есть цель — не мешать живой записи — достигнута. Строки в окне нет: человеку тут делать нечего.

## Проверяемость

Тестового проекта для `Cli` нет, обвязка под две строки несоразмерна (так же решено в #44). Проверка — живыми
прогонами.

## Критерии готовности слайса

1. Живой `meeting refine` под `nice -n 19` (сборка из ветки, WSL) на синтетической встрече без речи: до правки —
   `Win32Exception`, после — отказ `Refine.NothingRecognized` (код 1), то есть уточнение дошло до распознавания.
2. Тот же прогон без `nice` — то же, что до правки.
3. `scripts/test.sh` зелёный, инспекция — 0; `docs/pitfalls.md` — грабля с пометкой, что обработано.

## Границы

- Приоритет на Windows не трогается: там `BelowNormal` выставляется всегда.
