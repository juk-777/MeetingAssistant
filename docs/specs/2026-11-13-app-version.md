# Скилл сверяет версию приложения записи с версией плагина

**Статус:** принята 13.11.2026. Issue: #31.

## Задача

Плагин и приложение записи обновляются разными командами: плагин — `claude plugin update`, приложение —
`install.ps1` (из скилла — `meeting-install`). Скилл предлагает установку, только когда приложения нет вовсе
(код 3). Стоит старое — `/meeting start` молча запускает его.

Правка, которая живёт в приложении (правило пробуждения, формат транскрипта, уточнение), до человека с обновлённым
плагином не доходит, и ни скилл, ни приложение об этом не говорят. Встреча записывается на старом, а сессия
работает по правилам нового скилла: обещанное скиллом (слово обращения) не срабатывает, и это выглядит как
зависшая сессия.

## Решения

### Сверка — в `meeting-start` и `meeting-refine`, до окна

Оба скрипта до открытия окна узнают версию приложения (`meeting --version`) и сравнивают её с версией плагина
(`version` из `.claude-plugin/plugin.json` того плагина, откуда запущен скрипт). Приложение старее — отказ
с кодом 4 и одной строкой: какая версия стоит, какая нужна, обновить — `meeting-install`. Окно не открывается.

Подключение к идущей встрече (`meeting-dir`, `meeting-watch`) и протокол не сверяют: запись уже идёт, обновить
приложение во время неё нельзя (установка откажет), а прерывать встречу ради версии — хуже.

- *Почему до окна и отказом:* после старта предлагать поздно — запись уже идёт на старом приложении, а установка
  во время встречи отказывает. Предупреждение без остановки читается, когда встреча уже записана.
- *Почему отдельный код:* скилл реагирует на код, а не на текст (как на код 3), и с кодом 4 ведёт другой разговор:
  приложение есть, его можно и не обновлять.
- *Отвергнуто:* сверка в самом приложении (`meeting start --expect-version`) — приложение не знает о плагине, а
  старое приложение новую опцию не поймёт вовсе: сверка должна жить на стороне, которая обновляется первой.

### Сравнение — по числам `X.Y.Z`; `0.0.0-dev` — своя сборка, без сверки

Версии сравниваются покомпонентно числами (`0.2.10` новее `0.2.9`). Сборка разработчика (`-dev` в конце, её
ставят `install-wsl.sh` и `install.ps1 -FromSource`) не сверяется: разработчик сам знает, что у него стоит.
Ответ `--version` не в виде `X.Y.Z` и не `-dev` — тоже отказ с кодом 4: версию не распознать, значит её не
выпускал релиз.

- *Почему:* все выпуски с `v0.1.0` несут версию из тега (`scripts/release-version.sh` сверяет тег с версией
  плагина), так что у выпущенного приложения ответ всегда `X.Y.Z`.

### Версия плагина — из `plugin.json` тремя каталогами выше скриптов

Путь `<скрипты>/../../../.claude-plugin/plugin.json` открывает система, и `..` после ссылки идёт от её цели: у
разработчика скилл стоит ссылкой `~/.claude/skills/meeting` на рабочую копию (`install-skill.sh`), и файл
находится в рабочей копии, а не в `~/.claude` (изменено 13.11.2026: в черновике был `pwd -P` — мутант без него
выжил, физический путь не нужен). Файла нет или в нём нет версии — сверка не делается (скилл скопирован вне
плагина: сравнивать не с чем), запуск идёт как раньше.

### Скилл: код 4 — предложить обновление, отказ от него не мешает записи

`SKILL.md`, шаг «Подключение» и раздел «Уточнение»: код 4 — передать пользователю строку отказа и спросить,
обновить ли приложение сейчас (только программа, около 53 МБ; модели остаются). Да — `meeting-install` в фоне,
как при коде 3, затем повтор шага. Нет — повтор с `MEETING_ANY_APP_VERSION=1`: скрипт сверку пропускает.

После установки повтор идёт тоже с `MEETING_ANY_APP_VERSION=1`: установка ставит последний релиз, новее ничего нет.
Так бывает, когда плагин уже обновлён из `main`, а тег ещё не поставлен (маркетплейс берёт плагин из ветки по
умолчанию): без флага скилл предлагал бы ту же установку по кругу.

- *Почему флаг, а не отказ:* человек перед созвоном без сети или без времени на загрузку должен записать встречу.
- *Отвергнуто:* предупреждение после старта — см. выше.

### README: при выпуске обновлять и плагин, и приложение

Раздел «Обновление и удаление» говорит, что выпуск меняет обе части, и что скилл заметит старое приложение сам.

## Проверяемость

- Приложение старее плагина (патч, минор, мажор; `0.2.9` против `0.2.10`) — `meeting-start` и `meeting-refine`
  выходят с кодом 4, окно не открывается, в отказе обе версии и `meeting-install`.
- Версии равны, приложение новее, сборка `-dev` — окно открывается, как раньше.
- Ответ `--version` не распознан — код 4.
- `MEETING_ANY_APP_VERSION=1` — окно открывается и со старым приложением.
- Нет приложения — по-прежнему код 3, а не 4.
- Скрипт, запущенный через ссылку на каталог скилла, находит `plugin.json` плагина; без `plugin.json` сверки нет.
- `meeting-dir` версию не спрашивает.

## Критерии готовности слайса

1. Тесты скилла на свойства выше — зелёные в WSL и в Git Bash (CI `skill-git-bash`); мутации сравнения (снять
   сверку, сравнивать строками, не пропускать `-dev`, не пропускать по флагу, не распознанная версия проходит,
   код 3 теряется) роняют свои тесты.
2. `SKILL.md` ведёт разговор по коду 4, как описано; README — раздел обновления; `docs/architecture.md` (скилл)
   и `docs/decisions.md` — решение со сверкой.
3. Живая проверка в WSL: установленное приложение 0.2.4, плагин из рабочей копии с поднятой версией —
   `/meeting start` предлагает обновление, отказ от него запускает запись.
4. `scripts/inspect.sh` — 0 (C# не меняется, прогон для порядка не нужен — только если правка заденет код).
5. Версия плагина поднята (меняется скилл).

## Границы

- Приложение новее плагина — не сверяется: подсказать обновить плагин может только сам плагин, а он старый.
- Сам `meeting.exe` версию плагина не знает и не проверяет.
- Обновление плагина остаётся ручным (`claude plugin update`): его скилл обновить не может.
