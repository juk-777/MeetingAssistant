# Грабли платформы

Проверенные факты о библиотеках, ОС и инструментах, на которых стоит проект: что ведёт себя не так, как ждёшь, и как
обойти. У каждого пункта — версия или дата проверки. Перед правкой кода в этих местах — свериться; новая грабля
проекта — сюда, а не в личные инструкции разработчика: другой разработчик и агент их не видят.

## Библиотеки и окружение

- **sherpa-onnx (C#, 2.0.1) VAD:** весь звук одним `AcceptWaveform` теряет почти всю речь, а границы фраз зависят от размера кусков — подавать ровно окнами Silero (`WindowSize`, 512 при 16 кГц), остаток держать у себя; неполное окно в конце не обрабатывается и `Flush`. Умолчание `MaxSpeechDuration` — 5 с. Без паузы перед речью Silero теряет её начало: фразы набора, вырезанные впритык (OpenSTT), по одной дают WER CTC 29.6 % против 20.2 % целиком — подавать потоком через паузу; поток через цифровую тишину без сброса пропускает больше коротких реплик, чем фраза с тишиной и сбросом (23.4 против 21.3 %, 13.11.2026). `max_speech_duration` — порог, а не предел: дольше него детектор берёт порог 0.9 и тишину 0.1 с (конец фразы — вероятность ≤ 0.75 в течение 0.1 с), буфер растёт без потери; при 20 с на записях созвонов p99 фразы 25 с, max 35.6 с (исходник `voice-activity-detector.cc` v2.0.1, 16.11.2026).
- **Whisper (whisper.cpp / Whisper.net 1.9.1) на CPU:** кодировщик считает окно 30 с целиком — короткий кусок стоит как полный (turbo q5_0, 8 потоков: ≈ 16 с на фразу любой длины, 1.84 к речи на фразах p50 6 с). Речь склеивать до 30 с на вызов (паузы вырезать VAD — на тишине Whisper выдумывает текст), время отрезков переводить обратно по карте кусков: 0.69–0.87 к речи. Отмена `ProcessAsync` бросает сразу, но нативный счёт куска дорабатывает до конца кодировщика (~13 с). `Whisper.net.Runtime` кладёт в publish рантаймы всех платформ (≈ 15 МБ лишнего) при любом RID. С опорой на прошлый вывод (без `WithNoContext`) turbo на записи с провалами уходит в петлю повторов (проверено 13.11.2026). `WithPrompt` действует и с `NoContext`, но берутся только последние `n_text_ctx/2 − 1` токенов (223 у turbo), начало молча срезается — вводная фраза в начале подсказки теряется первой; токенизатора в Whisper.net нет. Turbo копирует подсказку как образец текста: на чтении термины лучше, на живом разговоре — переход на английский и петли (подсказка-список) или обрывки подсказки «Термина:» в половине кусков (подсказка-фраза); словарь в подсказку не годится (13.11.2026).
- **PulseAudio / PipeWire (`libpulse-simple`):** запись без `pa_buffer_attr` сервер отдаёт кусками по `fragsize` на свой выбор — около 2 с: монитор WSLg приходил пачками раз в 2.04 с при среднем темпе реальном. `fragsize` = длина пакета (100 мс) → ожидание чтения ≤ 0.2 с (14.11.2026). `pa_strerror` — в `libpulse.so.0`, не в `-simple`. `LibraryImport` требует `AllowUnsafeBlocks`; поля структуры для P/Invoke ReSharper в positional `record struct` считает неиспользуемыми — `readonly struct` с полями. Без `sudo` библиотека для проверки — `apt-get download libpulse0 …` + `dpkg-deb -x`, `LD_LIBRARY_PATH` на `usr/lib/x86_64-linux-gnu` и его `pulseaudio/`; сервер WSLg — `PULSE_SERVER=unix:/mnt/wslg/PulseServer`.
- **Окно терминала на Linux из скрипта:** в Ubuntu 26.04 с рабочим столом `x-terminal-emulator` — Ptyxis без ключа `-e` (отказ на старте), `gnome-terminal` не стоит, стоит `xdg-terminal-exec` (команда — аргументами) (`apt-cache show ptyxis`, 15.11.2026). Порядок: `xdg-terminal-exec`, `ptyxis --`, `x-terminal-emulator -e`, `gnome-terminal --`, `konsole -e`, `xfce4-terminal -x`, `xterm -e`, отказавший на старте — следующий; запуск в фоне с отвязанными потоками (xterm живёт с окном). Дистрибутив в доках не называть, если от него зависит только имя пакета — дать имена по семействам.
- **sherpa-onnx 2.0.1 hotwords:** только transducer + `modified_beam_search` (у CTC нет). GigaAM v3 нужен `bpe_vocab` из `tokenizer.model` (`ai-sage/GigaAM-v3`, ветка модели; веса unigram) — в архиве sherpa его нет, словарь из `tokens.txt` с выдуманными весами ломает текст. Даже с верным словарём вставляют термины и теряют куски фраз (13.11.2026).
- **Windows из WSL и Git Bash (проверено 12.11.2026):**
  - Windows-процесс, запущенный из WSL (`powershell.exe`, `cmd.exe`), получает окружение Windows на момент старта WSL: переменную пользователя, заданную позже, не видит — читать её из реестра: `powershell.exe` + `[Console]::OutputEncoding=[Text.Encoding]::UTF8` + `[Environment]::GetEnvironmentVariable(name,'User')`.
  - `reg.exe query` для этого не годится: пишет в кодовой странице консоли (кириллица в значении теряется), `%…%` не раскрывает, а под Git Bash ключ `/v` уходит в путь MSYS (`MSYS_NO_PATHCONV=1`).
  - `[Environment]::GetEnvironmentVariable('Path','User')` раскрывает `%X%`: переписав `PATH` им, записи перестают следовать за `X` — читать `(Get-Item HKCU:\Environment).GetValue('Path','','DoNotExpandEnvironmentNames')`, писать тем же типом (`GetValueKind`).
  - Windows PowerShell 5.1 читает `.ps1` без BOM в кодовой странице ANSI — скрипт с кириллицей сохранять UTF-8 с BOM.
  - `meeting.exe`, опубликованный с общим рантаймом, ищет его в `DOTNET_ROOT` и Program Files, не в `%USERPROFILE%\.dotnet` — при SDK в профиле публиковать self-contained.
  - Закрытие окна консоли = `PosixSignalRegistration(PosixSignal.SIGHUP)` (`CTRL_CLOSE_EVENT`): отменить завершение нельзя, процесс снимается после возврата обработчика (≈ 5 с) — обработчик ждёт дочистку сам; снятие регистрации не ждёт уже идущего обработчика.
  - По RDP без перенаправления звука в сеансе нет ни динамиков, ни микрофона.
  - Git Bash (MSYS), запуская программу Windows, переделывает значение переменной окружения, начинающееся с `/` (`/x` → `C:/Program Files/Git/x`, `/tmp/x` → путь Temp); `https://…` и значения не с `/` не трогает. Исключить: `MSYS2_ENV_CONV_EXCL="…;PREFIX_"` (префикс имени, список через `;`). Проверка — настоящей Windows-программой (`cmd.exe //c "echo %X%"`): заглушка-скрипт перевода не видит (проверено 13.11.2026).
  - `ln -s` в Git Bash по умолчанию копирует, а не создаёт ссылку: тест «через ссылку» там пропускать.
  - Окно с bash того же дистрибутива из WSL: `Start-Process wsl.exe -ArgumentList '-d <имя> -e bash "<скрипт>" "<арг>"'` через `powershell.exe`, значения — переменными окружения с `WSLENV`. Имя дистрибутива — без кавычек: `wsl.exe` их не снимает и отвечает `WSL_E_DISTRO_NOT_FOUND`; пути с пробелами и кириллицей в кавычках доходят (проверено 16.11.2026). `wsl.exe` профиль не читает — путь к `claude` передавать явно.
  - Файл по пути `<ссылка на каталог>/../x` открывает ядро — `..` идёт от цели ссылки, `pwd -P` для этого не нужен; лексически `..` режет только `cd` (проверено мутантом 13.11.2026).
  - `dirname` Git Bash делит путь и по `\`; неинтерактивный Git Bash не задаёт `LANG` — `grep -P` отказывает («supports only unibyte and UTF-8 locales»), нужен `LC_ALL=C.UTF-8`. `jq` в Git for Windows нет.
  - System.Text.Json с `UnsafeRelaxedJsonEscaping` кириллицу пишет как есть, а символ вне BMP (эмодзи) — суррогатной парой `\uD83D\uDE00`, и `\u2028` тоже экранирует.
- **Claude Code для Windows (2.1.319, проверено 13.11.2026):** Bash и `Monitor` идут в Git Bash (без Git for Windows `Monitor` нет); рядом включён инструмент PowerShell. `${CLAUDE_SKILL_DIR}` подставляется как `D:/…`, «Base directory» — `D:\…`. Свой `~/.claude` (`C:\Users\<имя>\.claude`) — плагины и хуки отдельно от WSL. Git Bash он запускает новой группой процессов: Ctrl+C выключен (`ConsoleFlags` = 1 в `RTL_USER_PROCESS_PARAMETERS`) и наследуется потомками, даже окном в новой консоли — перед `Start-Process` окна вызвать `SetConsoleCtrlHandler(NULL, FALSE)` (P/Invoke через `Add-Type`), тогда потомок получает 0.
- **Приоритет процесса на Linux (.NET 10):** `Process.PriorityClass = BelowNormal` в процессе, запущенном под `nice -n 19`, бросает `Win32Exception (13): Permission denied` — без прав nice не понижается; `meeting refine` его ловит и идёт с тем приоритетом, что есть (#76, 19.11.2026). Какое nice даёт `BelowNormal`, не проверялось.
- **Консольная точка входа:** System.CommandLine 2.0 после Ctrl+C даёт действию 2 с (`InvocationConfiguration.ProcessTerminationTimeout`), потом завершает процесс — дочистку ставить явным сроком. Опции с `ValidateOnStart` без `host.StartAsync` (и без `ConsoleLifetime`, который сам ловит Ctrl+C) проверяет `services.GetRequiredService<IStartupValidator>().Validate()`.
- **NAudio 3.x:** `ISampleProvider.Read(Span<float>)` вместо `(float[], int, int)`; PCM 16 пишется множителем 32767, читается делителем 32768 — круговой путь неточен, сравнивать с допуском. `WasapiRecorder.CaptureAsync` (`NAudio.Wasapi` 3.3.0) пакеты с флагом `Silent` не отдаёт вовсе (их отдаёт только `DataAvailable`); аудиоклиент создаётся в `Build()`, инициализируется на первом `MoveNext` — отказ устройства возможен в обоих местах.

## Замеры

- Число в доку — только из скрипта репозитория (`CLAUDE.md`, «Правила проекта»): пробный прогон из scratchpad дал
  29.3, тот же режим скриптом — 29.6. Сверка с чужой таблицей — по колонке того же варианта модели: GigaAM v3 CTC и
  v3_e2e_ctc на OpenSTT расходятся на 1.1–1.4 пункта.
- Открытый набор не заменяет данные продукта: RNNT выиграл у CTC 1.1 пункта WER на OpenSTT (фразы ~2 с), а на
  записях настоящих созвонов писал на 4 % меньше слов и терял куски фраз > 20 с — переход отменили. Судья без
  эталона — третья модель по совпадению слов, а не по их числу: turbo сам выкидывает паразиты.
- Переписанный скрипт замера сохраняет прошлый режим ключом, пока его число стоит в доке: `interview_stereo.py`
  перевели с цифровой тишины вне фраз на шум, и строка «цифровая тишина» таблицы конца ответа перестала
  воспроизводиться — режим вернули ключом `--silence` (18.11.2026).
- `meeting replay` распознаёт медленнее темпа звука на длинной записи: события по часам с местом в звуке не
  сверяются — сверка по номеру строки события (`interview_replay_check.py`). Два `replay` одновременно в одном
  корне встреч — второй падает на `current.json.tmp` (`FileNotFoundException`): каждому прогону свой корень
  (17.11.2026).
