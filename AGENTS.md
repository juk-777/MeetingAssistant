# AGENTS.md

Зеркало `CLAUDE.md` для сторонних агентов. Инструкции для Claude Code в репозитории MeetingAssistant. Репозиторий публичный: всё, что нужно для работы над
проектом, — здесь и в `docs/`, а не в личных настройках разработчика.

## Что это

Локальный помощник на созвонах. Приложение под Windows пишет звук встречи двумя каналами (микрофон — «Я»,
системный звук — «Собеседники»), режет речь по паузам, распознаёт её на CPU и дописывает транскрипт в файл.
Рабочая сессия Claude Code того проекта, о котором идёт встреча, просыпается по событиям из файла событий,
читает новый кусок транскрипта и даёт короткие подсказки с источником или молчит. Задачи по ходу встречи
она отправляет в сессии других проектов.

Инструмент общий для любых проектов, он не привязан к одному репозиторию.

## Где что

- `CLAUDE.md` — первоисточник этого файла: правятся тем же проходом, отличаются только заголовком.
- `docs/architecture.md` — устройство: компоненты, форматы файлов, правила событий, скилл `/meeting`, контекст сессии.
- `docs/measurements.md` — замеры распознавания и задержки подсказки, с условиями, плюс сторонние замеры на той же машине.
- `docs/decisions.md` — принятые решения с причинами и отвергнутые варианты.
- `docs/development.md` — порядок разработки: слайс, тесты, мутации, инспекция, конвенции кода.
- `docs/specs/`, `docs/plans/` — спеки и планы слайсов, шаблоны `_template.md`.
- Задачи — GitHub Issues репозитория (`gh issue list`).
- `prototype/` — Python-прототип на sherpa-onnx (замер моделей, прогон записи в реальном темпе) и стенд Whisper.net.
  Это опора для замеров, а не код продукта.
- `models/`, `samples/` — модели и записи, вне git (`.gitignore`). Как скачать модели — `docs/measurements.md`.

## Правила проекта

- **Архитектура — Clean Architecture + DDD со всеми следствиями**: Domain / Application / Infrastructure / Cli,
  зависимости внутрь, богатая доменная модель (агрегат `Meeting`, правила пробуждения в домене), сценарии в
  Application командами и обработчиками, NAudio и sherpa-onnx — только в Infrastructure за портами. Раскладка —
  `docs/architecture.md`, «Структура кода». Решение владельца проекта, не упрощать «потому что маленький проект».

- **Всё в репозитории обезличено.** Ни названий реальных встреч, проектов, компаний и людей, ни дат встреч, ни путей
  к личным папкам, ни цитат и тем из расшифровок, ни терминов из словарей реальных проектов. Запись в доке —
  «запись рабочего созвона, 643 с», а не что это была за встреча. Перед коммитом — `grep` по своим файлам.
- **Звук и транскрипты встреч — голос и слова живых людей.** В git, issue, чаты и внешние сервисы не выносить.
  Хранить локально, в `samples/` (вне git). В Anthropic уходит только текст, который читает сессия Claude Code.
- **Приложение записи — нативный Windows-процесс**, не WSL: системный звук захватывается только из Windows,
  а WSL уже падала от нехватки памяти на sherpa (см. `docs/measurements.md`, «Сторонние замеры»).
- **Решения не пересматривать молча.** Выбор модели, событийная схема и прочее из `docs/decisions.md` меняются
  только после нового замера; новый замер — в `docs/measurements.md` с условиями.
- **Работа — слайсами по `docs/development.md`:** issue → спека (принимает владелец, до принятия кода нет) → план
  → этапы локальными коммитами в `main` → мутации → инспекция → `/juk-self-review` → `/juk-retro` → ревью
  владельца → пуш с `Closes #N`.
  Статус «закрыт» — после прогона критериев готовности, у каждого записано, чем подтверждён.
- Найденное попутно — новым issue. Issues публичные — правило обезличенности действует и на них.
- Числа в доках — только с условиями замера (машина, потоки, вход, WSL или Windows).
- **Пуш в `main` — только после финального ревью владельца.** Коммиты этапов копятся локально; агент пушит сам
  после того, как владелец посмотрел дельту и сказал пушить. Это исключение из личного правила «в защищённые
  ветки не пушить» — только для этого репозитория (участник один, откат стоит одного коммита), подтверждено
  владельцем 10.11.2026. Репозиторий публичный, поэтому перед пушем — проверка обезличенности по отправляемой
  дельте (`git diff origin/main..HEAD`). Force-push, переписывание истории и удаление веток — только по явной команде.

## Окружение

- Машина: i7-11700F, 16 потоков, без GPU; Windows + WSL2 (11.7 ГБ, своп под нагрузкой).
- Во время созвона тяжёлое (сборки, IDE) не запускается — процессор свободен.
- Приложение — net10.0. В WSL SDK 10 — сборка и тесты без WASAPI. На Windows SDK 10 лежит в
  `%USERPROFILE%\.dotnet`, а `dotnet` из `PATH` — это `C:\Program Files\dotnet` с SDK 8 и 9: из консоли собирать
  и запускать `%USERPROFILE%\.dotnet\dotnet.exe`. Захват звука работает только в Windows-процессе.
- Тяжёлое в WSL (сборки, прогоны моделей) — под лимитом памяти: `systemd-run --user --scope -p MemoryMax=5G
  -p MemorySwapMax=1G --quiet bash -c "…"`, сборки с `-m:1`. Глобальный OOM в WSL роняет всю пользовательскую сессию.
- Прототип: Python 3.12 + `sherpa-onnx` 2.0.1 + `numpy` (venv через `uv`, см. `prototype/README.md`).
