# MeetingAssistant

Локальный помощник на созвонах: запись двумя каналами, распознавание русской речи на CPU (GigaAM v3 через
sherpa-onnx), транскрипт в файл, подсказки рабочей сессии Claude Code по событиям — вопрос, термин, обращение.

Две части:
- **приложение записи `meeting`** — пишет микрофон («Я») и системный звук («Собеседники»), распознаёт речь
  и дописывает транскрипт в каталог встречи. Windows (WASAPI) и Linux (PulseAudio или PipeWire);
- **скилл `/meeting` для Claude Code** — сессия Claude Code запускает запись, просыпается по событиям
  и подсказывает: по проекту — из его кода и доков, по остальному — из знаний модели. В режиме собеседования рядом
  открывается окно быстрых подсказок — кандидату или интервьюеру. После встречи сессия пишет протокол, по команде —
  сверив с транскриптом Whisper.

Звук и файлы встречи хранятся на машине. Наружу (в Anthropic) уходит текст: весь транскрипт встречи, к которой
подключена сессия Claude Code, и оба транскрипта, когда она пишет протокол; в режиме собеседования окно подсказок
отправляет последние 30 строк транскрипта и заметки `--notes` (первые 30 КБ), а с `--screen` — снимки экрана. Звук
не уходит никуда; получатель текста тот же и на тех же условиях, что для кода проекта.

## Установка

### Приложение записи

#### Windows

PowerShell:

```powershell
iwr https://github.com/juk-777/MeetingAssistant/releases/latest/download/install.ps1 -OutFile $env:TEMP\ma-install.ps1 -UseBasicParsing
powershell -ExecutionPolicy Bypass -File $env:TEMP\ma-install.ps1
```

Из терминала WSL — то же через `powershell.exe`:

```bash
powershell.exe -c 'iwr https://github.com/juk-777/MeetingAssistant/releases/latest/download/install.ps1 -OutFile $env:TEMP\ma-install.ps1 -UseBasicParsing; powershell -ExecutionPolicy Bypass -File $env:TEMP\ma-install.ps1'
```

Скрипт берёт `meeting` из последнего релиза (со своим рантаймом .NET — ставить .NET не нужно), модели
распознавания из релиза sherpa-onnx и модель Whisper для уточнения встречи с Hugging Face — около 900 МБ, сверяет
контрольные суммы и ставит всё в `%LOCALAPPDATA%\MeetingAssistant`. Задаёт
переменные пользователя `Storage__MeetingsRoot` (корень встреч, по умолчанию `%USERPROFILE%\Meetings`; другой —
`-MeetingsRoot <каталог>`) и `Speech__ModelsDirectory`, добавляет `meeting` в `PATH` — виден в новом окне
терминала. Конкретная версия — `-Version v0.1.0`; установленная — `meeting --version`.

#### Linux

Дистрибутив не важен: нужны x86-64 с glibc (не Alpine), сервер звука PulseAudio или PipeWire, ICU для .NET (на
рабочем столе всё это стоит по умолчанию) и `curl`. Ещё нужна библиотека `libpulse`. Пакет называется `libpulse0`
в Debian и Ubuntu, `pulseaudio-libs` в Fedora, `libpulse` в Arch.

```bash
curl -fsSL https://github.com/juk-777/MeetingAssistant/releases/latest/download/install.sh | bash
```

Скрипт ставит то же, что в Windows, в `~/.local/share/meeting-assistant` и сверяет контрольные суммы. Ссылку
`meeting` кладёт в `~/.local/bin`. В `~/.profile` дописывает `Storage__MeetingsRoot`, `Speech__ModelsDirectory` и
`~/.local/bin` в `PATH`: они действуют со следующего входа в систему, сейчас — `source ~/.profile`. Корень встреч
по умолчанию — `~/Meetings`, другой — `| bash -s -- --meetings-root <каталог>`. Конкретная версия —
`--version v0.1.0`.

Запись — `meeting start "<имя>"` в терминале, остановка — Ctrl+C. Микрофон по умолчанию пишется в «Я», монитор
устройства вывода по умолчанию — в «Собеседники».

### Скилл `/meeting`

В Claude Code — на Linux, в WSL или прямо в Windows:

```
/plugin marketplace add juk-777/MeetingAssistant
/plugin install meeting@meeting-assistant
```

Claude Code прямо в Windows нужен Git for Windows: скрипты скилла — bash, их выполняет Git Bash, и без него
у Claude Code нет `Monitor`, на котором держатся подсказки. Плагины у Claude Code в WSL и в Windows свои — ставить
в том, где идёт работа.

На Linux окно записи открывается в терминале, выбранном в системе (`xdg-terminal-exec`). Его нет — в первом
найденном из `ptyxis`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `xterm`. Подсказка
всплывает через `notify-send`, если он есть. В WSL скилл записывает через Windows: без `powershell.exe` — отказ.

Приложение записи ещё не стоит — `/meeting start` предложит поставить его сам.

### Из исходников

В WSL — нужны .NET SDK 10, git, curl и python3; клон в любом каталоге:

```bash
git clone https://github.com/juk-777/MeetingAssistant.git && cd MeetingAssistant
./scripts/install-wsl.sh        # сборка meeting в WSL и установка в Windows
./scripts/install-skill.sh      # скилл — ссылкой на рабочую копию
./scripts/download-models.sh    # модели в models/ — для тестов (./scripts/test.sh), 240 МБ
```

В PowerShell, без WSL — нужны .NET SDK 10 (в `PATH` или в `%USERPROFILE%\.dotnet`) и git:

```powershell
git clone https://github.com/juk-777/MeetingAssistant.git; cd MeetingAssistant
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -FromSource
```

На Linux — нужны .NET SDK 10 (в `PATH` или в `~/.dotnet`), git и curl:

```bash
git clone https://github.com/juk-777/MeetingAssistant.git && cd MeetingAssistant
./scripts/install.sh --from-source
```

Сборки из исходников ставят модели так же, как установка из релиза; `-FromSource` и `--from-source` берут их из
`models/` репозитория, если они там есть. Ссылка `install-skill.sh` вместо плагина: правка скилла в рабочей копии видна
сразу. В Claude Code для Windows скилл из рабочей копии — `claude --plugin-dir plugins/meeting`. Порядок
разработки — `docs/development.md`.

## Как пользоваться

### Начать и закончить встречу

Откройте Claude Code в репозитории того проекта, о котором созвон: подсказки о проекте берутся из его кода,
доков, issue и памяти. В каталоге без проекта сессия отвечает на общие вопросы из знаний модели.

Скорость подсказки почти целиком задаёт ход модели: доставка события и чтение файлов — около секунды, остальное —
модель думает и пишет. Модель и effort сессии выбираются под встречу (`docs/measurements.md`, «Скилл `/meeting`:
общие подсказки и задержка по частям»).

- `/meeting start <имя> [файл словаря]` — открывает окно записи и подключает сессию к встрече. В окне видны
  устройства и что запись идёт; остановка — Ctrl+C или закрытие окна. После Ctrl+C окно показывает итог (строки,
  события, CPU и пик памяти) и ждёт клавишу.
- `/meeting` — подключиться к уже идущей встрече (запущенной `meeting start "<имя>"` в терминале),
  `/meeting <каталог встречи>` — к конкретной.
- Лучше в наушниках: без них микрофон слышит собеседников из динамиков, и их слова могут попадать в «Я»
  (насколько — проверяется в [#13](https://github.com/juk-777/MeetingAssistant/issues/13)).

### Когда сессия отвечает

Запись режет речь на фразы по паузам и дописывает их в транскрипт. Сессия просыпается не на каждую фразу,
а по поводу:

- **вопрос** — во фразе есть «?» и не меньше трёх слов;
- **термин** — фраза совпала со словарём встречи;
- **обращение** — во фразе слово «Агент» в любом падеже единственного числа: «агент, …», «спроси агента»,
  «передай агенту»;
- **накопилось** — минута речи без других поводов.

Проснувшись, сессия читает новые строки вместе со всей встречей и либо молчит, либо даёт подсказку: в чате сессии —
карточку (реплика, на которую ответ, суть, 2–4 строки деталей и источник — `файл:строка`, issue, документ — или
пометка `общее`), поверх звонка — всплывающее уведомление с одной сутью, оно приходит первым. Подсказки на телефон
(Remote Control) — если попросить о них сессию на встрече («присылай подсказки на телефон»). Факт о проекте —
только со сверкой по коду и докам; общий вопрос (технология, подход, «как лучше») —
ответ из знаний модели с пометкой `общее`, а если в проекте есть что добавить, — ещё строка о том, как у нас.

### Обращение к сессии

Скажите «Агент» и просьбу — сессия ответит по существу. Слово узнаётся в распознанном тексте, кто бы его ни
сказал. «Клод» не годится: распознавание пишет его как «клот», «флот» или теряет. Например:

- «Агент, где у нас задаётся таймаут оплаты?» — ответ с файлом и строкой;
- «Агент, есть ли issue про экспорт отчёта?»;
- «Агент, отправь в billing: поправить округление в счёте, срок пятница» — задача уходит в открытую сессию
  проекта billing с таймкодом и именем встречи; такой сессии нет — подсказка об этом и текст задачи, чтобы
  он не потерялся.

Вопрос можно и написать в чат сессии посреди встречи, в любом режиме: ответ — той же карточкой, по транскрипту
до этого момента.

Во время встречи сессия ничего не пишет наружу (коммиты, issue, чаты), не меняет файлы проекта и не запускает
долгое — только читает и подсказывает. Единственное исключение — задача в сессию другого проекта по просьбе.

### Словарь встречи (необязательно)

Без словаря утверждение — фраза без «?» и без обращения — будит сессию только через минуту накопленной речи.
Словарь будит её сразу, когда прозвучал термин проекта: сессия смотрит, что о нём говорят код и доки, и подсказывает,
если сказанное с ними расходится («платёж уходит партнёру сразу», а в коде — через очередь с повтором) или полезно
напомнить факт; сказать нечего — молчит.

Класть в словарь стоит то, о чём у проекта есть что сказать: свои компоненты, сервисы, интеграции, спорные решения.
Общие слова будят зря, а каждое пробуждение — ход модели. Файл — шаблон на строку (регулярное выражение, без учёта
регистра; пустые строки пропускаются). Обратные ссылки, проверки вперёд и назад, атомарные группы, условия и
повторы на десятки тысяч символов не поддерживаются: шаблон с ними отказывает на старте записи с номером строки.

```
биллинг
шлюз\w* оплат\w*
сверк[аиу] с банком
```

`/meeting start планирование glossary.txt`.

### Собеседование: вы — кандидат

`/meeting start <имя> --mode candidate [--context '<строка>'] [--notes <файл>]… [--model <модель>]` — запись и
отдельное окно подсказок. На каждую реплику собеседников окно сразу отвечает потоком: первая строка — суть ответа
(она же — во всплывающем уведомлении), дальше 3–4 тезиса; первая строка — около 3 с после реплики. Задание без «?»
(«Расскажите о …») тоже получает ответ; на реплику, где отвечать не на что, — `-`. Новая реплика обрывает
недописанный ответ.

- `--context` — о чём собеседование одной строкой («бэкенд на .NET, системный дизайн»).
- `--notes` — резюме, заметки о компании: на вопросы об опыте ответ опирается на них. Файлы копируются в каталог
  встречи; в запрос модели идут первые 30 КБ.
- `--model` — модель окна (`opus` по умолчанию, `sonnet`, `haiku`); замер скорости — `docs/measurements.md`,
  «Подсказка кандидату: быстрый путь».
- Окно зовёт `claude`, найденный в `PATH` сессии: без него режим не включится.

Сессия рядом подсказок не дублирует: отвечает на обращение «агент», а `/meeting протокол` пишет протокол
собеседования — какие вопросы задали, где ответ вышел слабым, что подготовить дальше, что узнал о компании. Ответы
окна — в `candidate.md` каталога встречи.

### Собеседование: вы — интервьюер

`/meeting start <имя> --mode interviewer [--context '<строка>'] [--notes <файл>]… [--model <модель>]` — запись и
отдельное окно подсказок. Когда кандидат закончил ответ, окно оценивает его: первая строка — `верно`, `неполно` или
`ошибка` и чего не хватило (она же — во всплывающем уведомлении), дальше 1–2 уточняющих вопроса. Конец ответа видит
приложение записи: кандидат говорил от 10 с, потом 2.5 с тишины или вы заговорили — конец ответа отмечается за
1–2.5 с, первая строка подсказки приходит ещё через 2–3 с (`docs/measurements.md`, «Конец ответа кандидата»).
Нужна подсказка раньше или по короткому ответу — напишите `оцени` в чат сессии.

- `--notes` — вакансия, требования, резюме кандидата; `--context` и `--model` — как у кандидата.
- Без наушников голос кандидата попадает в микрофон. Приложение не примет его за вашу речь, но если вы заговорите
  меньше чем через полсекунды после кандидата, конец ответа отметится только после того, как вы договорите.
- Второй интервьюер на звонке попадает в канал собеседников вместе с кандидатом: его реплика продлевает ответ —
  тогда `оцени`.

Сессия рядом подсказок не дублирует: отвечает на обращение «агент» и на вопросы текстом в чате, а `/meeting
протокол` пишет протокол — вопросы с оценкой ответов, вывод по кандидату, что проверить дальше. Подсказки окна — в
`interviewer.md` каталога встречи.

### Собеседование: экран

`--screen [<монитор>]` в любой роли — окно подсказок видит экран: задачу и код онлайн-кодинга, схему. Приложение
снимает монитор раз в секунду; когда экран сменился и 3 с не меняется (не чаще раза в 10 с), модель переписывает
его в текст — задачу и код дословно, — и последнее описание идёт в каждую подсказку. Кандидату новая задача на
экране сама даёт подсказку — ход решения, без вопроса голосом. Видео собеседников в окне звонка сменой не считается.

- Снимается весь монитор — что на нём открыто, уходит в Anthropic вместе с описанием. Номер монитора — только в
  Windows (1 — основной); на Linux снимается экран X целиком, сессия Wayland не поддерживается.
- `--screen-model` — модель описания экрана (`haiku` по умолчанию): описание должно успевать за набором кода.
- Снимки — в `screen/`, их список — `screen.log`, описания — `screen.md` каталога встречи.

### После встречи

`/meeting протокол [каталог]` — `protocol.md` в каталоге встречи: темы, решения, задачи (что, кто, срок)
и открытые вопросы с таймкодами; спорные места — с вариантами прочтения. Встреча ещё идёт — протокол помечен
неполным.

По умолчанию переработки после встречи нет: транскрипт пишется вживую GigaAM, протокол — по нему. Whisper
английские термины пишет точнее, но теряет их не реже, а стоит около часа работы на час встречи
(`docs/decisions.md`, «Turbo после встречи — не по умолчанию, по команде»).

Важную встречу можно уточнить: `/meeting уточнить [каталог]` (или `meeting refine <каталог>` в терминале)
открывает окно, где Whisper заново распознаёт речь `audio.wav` законченной встречи по каналам
в `transcript.whisper.md`. Ориентир — около длины речи; идёт фоном, с пониженным приоритетом, на 4 потоках.
Потоков больше — быстрее (на 8 — 0.7–0.9 длины речи), но и нагрузка выше: число задаёт переменная
`Speech__RefineThreads`, не больше половины логических процессоров: в Windows — переменная пользователя, действует
со следующего уточнения; на Linux — `export` в `~/.profile`, действует со следующего входа в систему. Модель Whisper
(574 МБ) ставит установка; приложение, поставленное раньше, обновляется той же командой установки — скилл
предложит это сам. Если Whisper не распознал ни одной фразы, окно покажет отказ `Refine.NothingRecognized`,
а прежний `transcript.whisper.md`, если был, останется. После уточнения `/meeting протокол` сводит оба
транскрипта: написание терминов и имён — из Whisper, расхождения в цифрах, сроках и именах — обоими вариантами
с таймкодом и отдельным разделом.

Встреча — каталог `<корень встреч>\<дата>_<время>_<имя>`:
- `audio.wav` — звук, левый канал «Я», правый «Собеседники»; `meeting replay audio.wav` прогоняет встречу заново;
- `transcript.md` — транскрипт: строка на фразу, `[чч:мм:сс] Я|Собеседники: текст` после служебных номера
  и времени (формат — `docs/architecture.md`);
- `events.log` — события записи: поводы, по которым просыпалась сессия, `конец ответа` для окна интервьюера и
  `конец записи`; `hints.md` — подсказки и молчания сессии;
- в режиме собеседования — `mode.json` (режим, контекст, модели), `notes.md` (заметки `--notes`), журнал окна
  `candidate.md` или `interviewer.md`, у интервьюера — `marks.log` (отметки `оцени`); с `--screen` — `screen/`
  (снимки смен экрана), `screen.log` и `screen.md` (описания);
- `transcript.whisper.md` — второй транскрипт, если встречу уточняли (`.part` — уточнение ещё идёт);
- `protocol.md` — протокол, если его просили.

Во время созвона тяжёлое (сборки, IDE) на той же машине лучше не запускать: распознавание идёт на CPU.
По RDP — с перенаправлением звука (воспроизведение и запись на этом компьютере), иначе в сеансе нет устройств:
`Audio.NoDevice`.

## Обновление и удаление

Выпуск меняет обе части — и приложение записи, и скилл: обновлять их вместе. Скилл, который новее приложения,
перед записью и уточнением скажет об этом сам и предложит обновить приложение.

- Приложение записи — та же команда установки (из исходников — `install-wsl.sh`, `install.ps1 -FromSource` или
  `install.sh --from-source`): программа заменяется, корень встреч и модели остаются, недостающие модели (Whisper
  у установки до уточнения встречи) докачиваются. В Windows во время встречи — отказ; на Linux идущая запись
  дорабатывает на прежней версии.
- Скилл — в терминале
  `claude plugin marketplace update meeting-assistant && claude plugin update meeting@meeting-assistant`,
  затем перезапуск сессии Claude Code.
- Удаление: `/plugin uninstall meeting@meeting-assistant` (или ссылка `~/.claude/skills/meeting`), каталог
  `%LOCALAPPDATA%\MeetingAssistant`, переменные пользователя `Storage__MeetingsRoot` и `Speech__ModelsDirectory`,
  строка `…\MeetingAssistant\app` в `PATH` пользователя. На Linux — каталог `~/.local/share/meeting-assistant`,
  ссылка `~/.local/bin/meeting` и блок `meeting-assistant` в `~/.profile`.
