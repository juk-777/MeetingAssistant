# MeetingAssistant

Локальный помощник на созвонах: запись двумя каналами, распознавание русской речи на CPU (GigaAM v3 через
sherpa-onnx), транскрипт в файл, подсказки рабочей сессии Claude Code по событиям — вопрос, термин, обращение.

Две части:
- **приложение записи `meeting`** — пишет микрофон («Я») и системный звук («Собеседники»), распознаёт речь
  и дописывает транскрипт в каталог встречи. Пока только Windows: звук захватывается через WASAPI; Linux —
  [#16](https://github.com/juk-777/MeetingAssistant/issues/16);
- **скилл `/meeting` для Claude Code** — сессия Claude Code запускает запись, просыпается по событиям
  и подсказывает: по проекту — из его кода и доков, по остальному — из знаний модели; после встречи пишет протокол, по команде — сверив
  с транскриптом Whisper.

Звук и файлы встречи хранятся на машине. Наружу (в Anthropic) уходит текст: весь транскрипт встречи, к которой
подключена сессия Claude Code, и оба транскрипта, когда она пишет протокол. Звук не уходит никуда; получатель
текста тот же и на тех же условиях, что для кода проекта.

## Установка

### Приложение записи

PowerShell:

```powershell
iwr https://github.com/juk-777/MeetingAssistant/releases/latest/download/install.ps1 -OutFile $env:TEMP\ma-install.ps1 -UseBasicParsing
powershell -ExecutionPolicy Bypass -File $env:TEMP\ma-install.ps1
```

Из терминала WSL — то же через `powershell.exe`:

```bash
powershell.exe -c 'iwr https://github.com/juk-777/MeetingAssistant/releases/latest/download/install.ps1 -OutFile $env:TEMP\ma-install.ps1 -UseBasicParsing; powershell -ExecutionPolicy Bypass -File $env:TEMP\ma-install.ps1'
```

Скрипт берёт `meeting` из последнего релиза (со своим рантаймом .NET — ставить .NET не нужно), модели
распознавания из релиза sherpa-onnx и модель Whisper для уточнения встречи с Hugging Face — около 900 МБ, сверяет
контрольные суммы и ставит всё в `%LOCALAPPDATA%\MeetingAssistant`. Задаёт
переменные пользователя `Storage__MeetingsRoot` (корень встреч, по умолчанию `%USERPROFILE%\Meetings`; другой —
`-MeetingsRoot <каталог>`) и `Speech__ModelsDirectory`, добавляет `meeting` в `PATH` — виден в новом окне
терминала. Конкретная версия — `-Version v0.1.0`; установленная — `meeting --version`.

### Скилл `/meeting`

В Claude Code — в WSL или прямо в Windows:

```
/plugin marketplace add juk-777/MeetingAssistant
/plugin install meeting@meeting-assistant
```

Claude Code прямо в Windows нужен Git for Windows: скрипты скилла — bash, их выполняет Git Bash, и без него
у Claude Code нет `Monitor`, на котором держатся подсказки. Плагины у Claude Code в WSL и в Windows свои — ставить
в том, где идёт работа.

Приложение записи ещё не стоит — `/meeting start` предложит поставить его сам.

### Из исходников

В WSL — нужны .NET SDK 10, git, curl и python3; клон в любом каталоге:

```bash
git clone https://github.com/juk-777/MeetingAssistant.git && cd MeetingAssistant
./scripts/install-wsl.sh        # сборка meeting в WSL и установка в Windows
./scripts/install-skill.sh      # скилл — ссылкой на рабочую копию
./scripts/download-models.sh    # модели в models/ — для тестов (./scripts/test.sh), 250 МБ
```

В PowerShell, без WSL — нужны .NET SDK 10 (в `PATH` или в `%USERPROFILE%\.dotnet`) и git:

```powershell
git clone https://github.com/juk-777/MeetingAssistant.git; cd MeetingAssistant
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -FromSource
```

Обе сборки из исходников ставят модели так же, как установка из релиза; `-FromSource` берёт их из `models/`
репозитория, если они там есть. Ссылка `install-skill.sh` вместо плагина: правка скилла в рабочей копии видна
сразу. В Claude Code для Windows скилл из рабочей копии — `claude --plugin-dir plugins/meeting`. Порядок
разработки — `docs/development.md`.

## Как пользоваться

### Начать и закончить встречу

Откройте Claude Code в репозитории того проекта, о котором созвон: подсказки о проекте берутся из его кода,
доков, issue и памяти. В каталоге без проекта сессия отвечает на общие вопросы из знаний модели.

Скорость подсказки почти целиком задаёт ход модели: доставка события и чтение файлов — около секунды, остальное —
модель думает и пишет. Модель и effort сессии выбираются под встречу (`docs/measurements.md`, «Скилл `/meeting`:
общие подсказки и задержка по частям»).

- `/meeting start <имя> [файл словаря]` — открывает окно записи и подключает сессию к встрече. В окне видны
  устройства и что запись идёт; остановка — Ctrl+C или закрытие окна. После Ctrl+C окно показывает итог (строки,
  события, CPU и пик памяти) и ждёт клавишу.
- `/meeting` — подключиться к уже идущей встрече (запущенной `meeting start "<имя>"` в терминале Windows),
  `/meeting <каталог встречи>` — к конкретной.
- Лучше в наушниках: без них микрофон слышит собеседников из динамиков, и их слова могут попадать в «Я»
  (насколько — проверяется в [#13](https://github.com/juk-777/MeetingAssistant/issues/13)).

### Когда сессия отвечает

Запись режет речь на фразы по паузам и дописывает их в транскрипт. Сессия просыпается не на каждую фразу,
а по поводу:

- **вопрос** — во фразе есть «?» и не меньше трёх слов;
- **термин** — фраза совпала со словарём встречи;
- **обращение** — во фразе слово «Агент»;
- **накопилось** — минута речи без других поводов.

Проснувшись, сессия читает новые строки вместе со всей встречей и либо молчит, либо даёт подсказку в 2–3 строки
с источником (`файл:строка`, issue, документ) или с пометкой `общее`. Подсказка — в терминале сессии
и всплывающим уведомлением Windows, которое видно поверх звонка; при подключённом Remote Control — ещё и на
телефоне. Факт о проекте — только со сверкой по коду и докам; общий вопрос (технология, подход, «как лучше») —
ответ из знаний модели с пометкой `общее`, а если в проекте есть что добавить, — ещё строка о том, как у нас.

### Обращение к сессии

Скажите «Агент» и просьбу — сессия ответит по существу. Слово узнаётся в распознанном тексте, кто бы его ни
сказал. «Клод» не годится: распознавание пишет его как «клот», «флот» или теряет. Например:

- «Агент, где у нас задаётся таймаут оплаты?» — ответ с файлом и строкой;
- «Агент, есть ли issue про экспорт отчёта?»;
- «Агент, отправь в billing: поправить округление в счёте, срок пятница» — задача уходит в открытую сессию
  проекта billing с таймкодом и именем встречи; такой сессии нет — подсказка об этом и текст задачи, чтобы
  он не потерялся.

Во время встречи сессия ничего не пишет наружу (коммиты, issue, чаты), не меняет файлы проекта и не запускает
долгое — только читает и подсказывает. Единственное исключение — задача в сессию другого проекта по просьбе.

### Словарь встречи (необязательно)

Без словаря утверждение — фраза без «?» и без обращения — будит сессию только через минуту накопленной речи.
Словарь будит её сразу, когда прозвучал термин проекта: сессия смотрит, что о нём говорят код и доки, и подсказывает,
если сказанное с ними расходится («платёж уходит партнёру сразу», а в коде — через очередь с повтором) или полезно
напомнить факт; сказать нечего — молчит.

Класть в словарь стоит то, о чём у проекта есть что сказать: свои компоненты, сервисы, интеграции, спорные решения.
Общие слова будят зря, а каждое пробуждение — ход модели. Файл — шаблон на строку (регулярное выражение, без учёта
регистра; пустые строки пропускаются):

```
биллинг
шлюз\w* оплат\w*
сверк[аиу] с банком
```

`/meeting start планирование glossary.txt`.

### После встречи

`/meeting протокол [каталог]` — `protocol.md` в каталоге встречи: темы, решения, задачи (что, кто, срок)
и открытые вопросы с таймкодами; спорные места — с вариантами прочтения. Встреча ещё идёт — протокол помечен
неполным.

По умолчанию переработки после встречи нет: транскрипт пишется вживую GigaAM, протокол — по нему. Whisper
английские термины пишет точнее, но теряет их не реже, а стоит около 40 минут работы на час встречи
(`docs/decisions.md`, «Turbo после встречи — не по умолчанию, по команде»).

Важную встречу можно уточнить: `/meeting уточнить [каталог]` (или `meeting refine <каталог>` в терминале)
открывает окно, где Whisper заново распознаёт речь `audio.wav` законченной встречи по каналам
в `transcript.whisper.md`. Ориентир — 0.7–0.9 длины речи; идёт фоном, с пониженным приоритетом. Модель Whisper
(574 МБ) ставит установка; приложение, поставленное раньше, обновляется той же командой установки — скилл
предложит это сам. После уточнения
`/meeting протокол` сводит оба транскрипта: написание терминов и имён — из Whisper, расхождения в цифрах, сроках
и именах — обоими вариантами с таймкодом и отдельным разделом.

Встреча — каталог `<корень встреч>\<дата>_<время>_<имя>`:
- `audio.wav` — звук, левый канал «Я», правый «Собеседники»; `meeting replay audio.wav` прогоняет встречу заново;
- `transcript.md` — транскрипт: строка на фразу, `[чч:мм:сс] Я|Собеседники: текст` после служебных номера
  и времени (формат — `docs/architecture.md`);
- `events.log` — поводы, по которым просыпалась сессия; `hints.md` — её подсказки и молчания;
- `transcript.whisper.md` — второй транскрипт, если встречу уточняли (`.part` — уточнение ещё идёт);
- `protocol.md` — протокол, если его просили.

Во время созвона тяжёлое (сборки, IDE) на той же машине лучше не запускать: распознавание идёт на CPU.
По RDP — с перенаправлением звука (воспроизведение и запись на этом компьютере), иначе в сеансе нет устройств:
`Audio.NoDevice`.

## Обновление и удаление

Выпуск меняет обе части — и приложение записи, и скилл: обновлять их вместе. Скилл, который новее приложения,
перед записью и уточнением скажет об этом сам и предложит обновить приложение.

- Приложение записи — та же команда установки (из исходников — `install-wsl.sh` или `install.ps1 -FromSource`):
  программа заменяется, корень встреч и модели остаются, недостающие модели (Whisper у установки до уточнения
  встречи) докачиваются. Во время встречи — отказ.
- Скилл — в терминале
  `claude plugin marketplace update meeting-assistant && claude plugin update meeting@meeting-assistant`,
  затем перезапуск сессии Claude Code.
- Удаление: `/plugin uninstall meeting@meeting-assistant` (или ссылка `~/.claude/skills/meeting`), каталог
  `%LOCALAPPDATA%\MeetingAssistant`, переменные пользователя `Storage__MeetingsRoot` и `Speech__ModelsDirectory`,
  строка `…\MeetingAssistant\app` в `PATH` пользователя.
